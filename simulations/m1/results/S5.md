# M1-S5: timing metadata across the Ethernet – 5G – Ethernet bridge (results)

**Verdict: PASS** (all 8 rows of `S5/check.txt`). The S1–S4 regressions are unchanged.

**Main finding:**
- Frame bytes cross the bridge intact, and so does the application's chunk-level creation-time tag.
- The INET MeasurementLayer tags (packet-level region tags) do **not** cross the 5G system. Unmodified Simu5G 1.8.0 drops them.
- Per-frame ingress/egress times and 5G-system residence are therefore available only by observation (PCAP), not as metadata travelling with the frame.
- No component writes residence time into any frame: **transparent-clock correction is not supported in M1**.

## What S5 is

`[Config S5]` is S4 (gPTP grandmaster behind nwTt, slave behind dsTt, S2 application flows) plus:
- **Packet identity in the frame:** the application payload is INET's `ApplicationPacket`, 4 B length + 4 B sequence number per flow.
- **Instrumentation:** INET `MeasurementLayer` on both translators' 5G-side ports. It starts a `transit5gs` flow tag and an elapsed-time tag on every frame sent into the 5G system, and records them at the far translator.
- **Replay data:** TX-side RLC SDU vectors, so that SDUs cut and reassembled by the DL tail lag (`O-tail.md`) can be named.

**Controls** (all PASS): none of these additions changes a sample.
- S5 without measurement layers = S4.
- S5 = S5 without measurement layers.
- S5-pcap = S5.

These hold for the delay, pdelay and slave-clock samples, seed 0.

## Metadata, by where it lives

| Metadata | In the frame (wire) | With the frame, in simulation only | By observation only | Evidence (row) |
|---|---|---|---|---|
| Packet identity: application sequence number; gPTP message type + sequence ID | **Yes**, preserved | — | — | W-identity: every frame leaving the 5G system carries the identity and the bytes it entered with: once, in order per flow. This includes 276 DL SDUs that were cut and reassembled. |
| gPTP origin/receipt/response timestamps | **Yes**, preserved unchanged | — | — | W-identity (bytes), W-gptp |
| Residence time in the frame (gPTP `correctionField`) | **Not written**: 0 at both ends for all 187 gPTP frames | — | — | W-gptp. No transparent-clock correction. |
| Application creation time (INET `CreationTimeTag`, chunk-level) | — | **Yes**, preserved with the correct value | — | C-creation: 979/979 received frames; lifetime = reception − send time of that sequence number |
| Translator ingress/egress time stamps (INET `MeasurementLayer` flow + elapsed-time tags, packet-level region tags) | — | **No**, dropped inside the 5G system | — | R-ingress: present on every frame up to the last INET module before the 5G core/RAN. R-egress: 0 transit samples at the far translator in all 10 seeds, while all frames arrive. |
| Per-frame ingress/egress time at the translators and 5G-system transit | — | — | **Yes**, reconstructed by identity | O-transit: every frame that crossed (seed 0) |

**Why the region tags are lost** (code reading, consistent with R-ingress/R-egress; not isolated further):
- INET keeps measurement and flow tags as packet-level region tags (`Packet::regionTags`).
- Simu5G's `GtpUser` builds a new `Packet` from the old one's data (`new Packet(...)` + `insertAtBack(datagram->peekData())`) when it tunnels and again when it decapsulates.
- Chunk-level tags such as `CreationTimeTag` travel with the data; packet-level region tags stay behind.
- In DL the tags are verifiably present in the UPF's Ethernet bridge up to its FCS inserter, the last INET module before `GtpUser`.

These are observations, not metadata carried by the frames. They are exactly what a time-aware translator (M2) would have to measure itself and write into the frame (for example into `correctionField`). M1 shows that the information is observable at the translator ports; it does **not** show that it can be carried or used.

## What S5 does not claim

- No transparent-clock or residence-time correction exists in M1. `correctionField` stays 0.
- No in-simulation tag carries translator timestamps across the 5G system on unmodified Simu5G 1.8.0. A chunk-level tag set by a translator might survive, as `CreationTimeTag` does, but that needs code that M1 does not have, and it has not been tested.
- INET packet-level (non-region) tags were not tested separately.
