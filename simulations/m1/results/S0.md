## Observations (recorded, not yet attributed)

1. **UL delay is deterministic in shape.** In seed 0 it takes 14 discrete values between 6 and 47 ms in a repeating pattern (about 30 frames each). It does not spread like a random channel effect. A candidate cause is the grant/BSR cycle without a modelled Scheduling Request (inventory blocker B10), but this is **not established**. Attribution needs a dedicated test (e.g. varying `retxBsrTimer` / RAC parameters). This matters for every UL latency figure nascTime reports.
2. **DL delay is identical across all 10 seeds.** No seed-dependent effect reaches the DL path in this configuration (good channel, one UE, no fading-induced HARQ retransmissions visible). DL seed sweeps in this setup therefore carry no statistical information.
3. **Per-PCP delay cannot be separated in this upstream config.** Both PCP flows share one sink with the same frame length. S0 therefore records per-direction delay (deviation from the plan's S0 wording). S3 will separate PCPs by giving each PCP a distinct frame length, which needs no code.
4. Region tags (INET `CreationTimeTag` on payload chunks) survive the full Ethernet-session path in both directions: every received frame produced a lifetime sample. This is early evidence for S5(a).
