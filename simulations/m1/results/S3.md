## What S3 is

`[Config S3]` is the S2 network (pass-through translators on) with a flow matrix in each direction:

- **Flows:** `talker` and `listener` each send nine flows to the other.
  - VLAN 42 with PCP 0–7 (`app[0..7]`), payload 100 B + 20 B × PCP.
  - One untagged flow (`app[8]`), payload 300 B.
  - One frame per 20 ms per flow; flows start 2 ms apart.
  - Every flow has its own frame length, so a frame's flow can be identified anywhere in the 5G system.
- **Mapping (identical rules in both directions):**

| Traffic | QFI | DRB |
|---|---|---|
| PCP 5 | 5 | 2 (`mappedQfis: [5]`, LCG 1) |
| PCP 6 | 6 | 3 (`mappedQfis: [6]`, LCG 2) |
| PCP 0–4, 7, untagged | 0 (default flow) | 1 (`isDefault`, LCG 3) |

Rules are `dlQfiRules` and `ulQfiRules` with Simu5G's `ieee8021qctag.pcp` filter; DRBs are `staticDrbs`. All are plain ini.

## How QFI and DRB are observed, separately, per direction

| | Uplink | Downlink |
|---|---|---|
| **QFI** (classification) | N3 PCAP: QFI in the GTP-U PDU Session Container of every G-PDU with PDU type 1 (gNB → UPF). This is the UE's classification. It reaches the gNB in the SDAP header (default DRB), or is implied by a headerless DRB; the UE's SDAP stops with an error if the classified QFI differs from what the DRB implies. | N3 PCAP: G-PDUs with PDU type 0 (UPF → gNB). This is the UPF's classification. |
| **DRB** (actual assignment) | SDU sizes at the UE's RLC TX entity of each DRB, and at the gNB's RLC RX entity of each DRB | SDU sizes at the gNB's RLC TX entity, and at the UE's RLC RX entity |

- Simu5G creates one RLC entity per DRB, named `…-um-<node>-<drbId>`.
- The SDU-size vectors are standard statistics: on by default on the RX side, and switched on by result recording on the TX side.
- Because every flow has a distinct frame length, each SDU names its flow.
- The checker compares every observation against the intended mapping above. It does not compare against the configuration of the run, so a wrong configuration fails.

### Negative controls (seed 0, with PCAP)

Each control changes one thing. It must fail **exactly** the listed rows and pass all others.

| Config | Change | Must fail | Result |
|---|---|---|---|
| `S3-neg-absent` | Rules for VLAN 43 (no such traffic), placed first in both rule lists | nothing; delay samples bit-identical to S3-pcap | PASS: no row fails, samples bit-identical |
| `S3-mut-ul-swap` | UL rules swapped (PCP 5 → QFI 6, PCP 6 → QFI 5) | Q-UL, D-UL-tx, D-UL-rx | PASS: exactly those. PCP 5 rides DRB 3 with QFI 6 and PCP 6 rides DRB 2 with QFI 5, in UL only. |
| `S3-mut-dl-swap` | DL rules swapped | Q-DL, D-DL-tx, D-DL-rx | PASS: exactly those, DL only |
| `S3-mut-drb-swap` | QFI → DRB mapping swapped (DRB 2 ← QFI 6, DRB 3 ← QFI 5); rules unchanged | the four D rows; Q rows must pass | PASS: QFIs correct in both directions, DRBs swapped in both |

What the controls establish:
- The UL and DL checks are independent of each other.
- The QFI checks and the DRB checks observe different things: classification versus QFI → DRB mapping.
- A rule that matches nothing has no side effect.

## Open observation O-S3-1 (explained later, see `O-S3-1.md`)

As recorded at S3: under saturating load (S3-load), 11–28 % of the frames that a DRB's RLC TX entity accepted were never delivered by the peer RLC RX entity, and no drop statistic recorded them.

**Explained (2026-10-12):** Simu5G's MAC deletes a whole MAC PDU, including the RLC PDUs already taken from the RLC, when it builds a transport block while all 5 HARQ processes are waiting for feedback. The HARQ round trip is exactly 5 slots. No statistic counts the deletion.
- Excluded: end-of-run, queueing and radio loss.
- Confirmed: the MAC discard, PDU-exact.
- Counterfactual: 16 HARQ processes remove it.

A one-frame residual is open as O-S3-2. None of this changes any S3 check.

## Conclusion

On unmodified Simu5G 1.8.0, the configured VLAN/PCP → QFI → DRB mapping is applied correctly and independently in each direction.
- Classification (the QFI on N3) and DRB assignment (the RLC entity used) are verified separately, frame by frame, for all nine flows. The mapping also holds under saturating load.
- The negative controls show that each check fails exactly when its own part of the configuration is wrong.
- PCP and VLAN survive the 5G system byte-identically.
