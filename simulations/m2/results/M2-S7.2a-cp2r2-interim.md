### 2.4 Finding: periodic pair loss for the loaded UE (`loss-localisation.txt`)

Under the asymmetric load, ue[1] never transmits towards dsTt[1] about every sixth Sync/Follow_Up pair: sequenceIds 5, 11, 17, 23, 29, 35, 41, …, with occasional spacing 5. Specifically:
- the same sequence numbers in Q-0 and Q-d;
- the same count at 0.25 ms and 1 ms load (Q-d: 17 Syncs over the run, 30 cohort frames);
- Q-0 additionally loses some Follow_Ups (e.g. 6, 7, 12, 18) and shows hold / release.

The loss is not present in Block B: idle, every seed, all 95 cohort pairs delivered to every UE. N3 carries every copy on every tunnel (F0-1 N3 part), and F0-5 shows 192/192 SDUs entering the gPTP DRB for both UEs. So the pairs are lost between the gNB DRB entry and the UE's Ethernet egress.

**Not investigated further:** the mechanism (RLC, HARQ or MAC discard, grant cutting). That is failure isolation, and it needs approval.

### 2.5 Q-d (UM) observation

On Q-d, delivered gPTP frames have identical residences for the loaded and unloaded UE (0 of 79 differ). The dedicated priority DRB isolates gPTP timing from the load. On Q-d, cross-slave heterogeneity arises only from the lost pairs, which cause the different-Sync samples.

## 3. Proposal (for approval; nothing implemented)

**P1. Localise the periodic UE 1 pair loss (read-only).**
- **Evidence:** the RLC TX/RX vectors and PDU sizes that M2S71-base already records, plus the gNB and UE PCAPs and the eventlog, on the existing trial run H-qdu-Ca-n2 seed 0.
- **Question:** for each lost pair, the last module that held the SDU (gNB RLC TX entity of DRB 4, MAC/HARQ, UE RLC RX), and whether the pattern matches M1 L1 (HARQ discard, 5 processes) or L2 (grant cut).
- **Constraints:** no code or config changes, no new oracle. Output: a short evidence note. This is failure isolation for one observed pattern; it is not Stage 6.

**P2. Loss-free perturbation, one probe each, results reported before any record.**
- **(a)** Block H with the existing `M2S0-harq16` mixin (16 HARQ processes). This is the S7.1 counterfactual that removed MAC discard. A generated config `M2S72-H16-q0-Ca-n2`, no C++. It applies only if P1 points to HARQ discard.
- **(b)** If losses persist, a narrowly controlled timing perturbation with no loss mechanism. One candidate is a fixed per-UE DL base-flow phase offset on UE 1. It would be specified, with its expected effect on residences, before any run.
- **(c)** If loss is inherent to loaded operation, an explicit ruling instead: loss- and hold-accounting forms of F0-1 and I-2 for Block H runs only. Every cohort pair would be required to be delivered, or accounted as not delivered by the RAN to that UE, and never duplicated, misdirected or alien. Every hold would have to be released with the identical tag. This is an acceptance-criteria change and needs approval.

**P3.** Restrict Block H to Q-0, since Q-d does not produce residence heterogeneity. Keep Q-d reported as an observation.

After approval, the Checkpoint 2 rev. 2 record would be produced with predictions and any amended criteria committed before the run, as in `61b68d4`.
