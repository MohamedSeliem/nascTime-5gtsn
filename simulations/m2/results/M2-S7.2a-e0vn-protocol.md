## 4. Per-run evaluation (unchanged code)

**One process per run:**

```
python3 -I -B check/check_m2s72_s5n21.py run <runs> <cfg> <records>/<cfg>
```

WP-A1 design §5.4. It evaluates the accepted s5n rows at N (`check_m2s72_s5n.py`, unchanged) and the wrapper rows from one A-2.1 replay.

| Class | Rows |
|---|---|
| **Gates** (a FAIL or NE stops the batch) | Every s5n gate except PU-4: Block B F0-2 … F0-8, I-1 … I-4, M2 / M3 / M3d / M4, I-2H, per-UE Q8, Q8-v, SG-403, MG-1, PU-1, PU-2 ×N, PU-3 ×N, PU-5, AV-1 … AV-3 ×N. Plus the wrapper rows MAP-UE, C-0, PU-4h (run) and PU-4o, A2-8u (UE 0 … N − 1). |
| **Reported, never gating** | PU-4 (A-1, verbatim); F0-1 (info); EOR (not applicable); the A-2.1 `full` verdict; the run-level A2-8; the agreement diagnostic; every per-UE and across-UE measurement |

**Expected-row completeness, checked twice:**
- by the wrapper itself (design §4.9: a missing s5n row is exit 2);
- independently by `m2s72_e0vn_batch.py outcome`. A composed digest is a bracket result only if its wrapper rows are **exactly** {MAP-UE, C-0, PU-4h} (run) ∪ {PU-4o, A2-8u} × {UE 0 … N − 1}, all PASS or NX, with `numUe` = N and N per-UE performance entries. Otherwise the run is refused and the batch stops.

**Bracket outcome of a run** (`m2s72_e1sel.classify`, unchanged), on the composed digest's `performance.across`:

| Outcome | Rule |
|---|---|
| `ok` | no UE overloaded or starved |
| `overloaded` | some UE overloaded (per UE: sustained load-DRB backlog growth **and** achieved < offered) |
| `starved` | no UE overloaded, some UE starved |
| `invalid` | a non-OK run outcome, a wrapper exit ≠ 0, or an overload class not evaluable |

Only a PASS verdict gives `ok` / `overloaded` / `starved`.

## 5. Batch procedure

### 5.1 Per combination (B-1 … B-4, unchanged)

1. **Start:** factor 1.0.
   - **HARQ5 with S5-2-D5 approved:** start at the HARQ16 f_lo of the same (option, placement, N), read from the **committed** HARQ16 bracket record. A HARQ16 combination without f_lo makes the HARQ5 start impossible, and the batch stops.
2. **Step:** up after `ok`, down after a non-ok. When f_lo and f_hi are adjacent on the ladder, **one confirmation run above f_hi** (unless f_hi is the top).
3. **Stop:**

   | Status | Meaning | Batch |
   |---|---|---|
   | `bracketed` | f_lo and f_hi adjacent, confirmation done | continues |
   | `top` | `ok` at 2: f_lo = 2, f_hi unknown, never extrapolated | continues |
   | `non-monotone` | an `ok` above a non-ok | **stops (exit 8)** |
   | `below ladder` | non-ok at 0.5 | **stops (exit 8)** |
   | `invalid` | §4 | **stops** with that run's exit code |

The state machine is the accepted `m2s72_e1sel.Bracket`. The runner never decides a step itself: every next factor is `m2s72_e0vn_batch.py next`, replayed from the record `bracket.tsv`. A row that the state machine refuses is an error (exit 6).

### 5.2 Per run (one simulation at a time; S5-1 lifecycle)

1. Free-space rule: free ≥ 1.5 × S5_E0VN_RUN_BYTES + 0 (no twin) + 1 GB + 2 GB (`m2s72s5_lib.py space`).
2. The simulation: the exact argument vector of `m2s72_e0vn_batch.py cmd`, recorded in `commands.tsv`, under `timeout S5_E0VN_RUN_LIMIT_S`, non-express, MAC logs to `run-<cfg>.log.gz` (`gzip -n`).
3. Outcome classification.
4. Manifest: sha256 and size of every raw file, fsync'd.
5. The per-run evaluation (§4), its records under `records/<cfg>/`.
6. The bracket outcome, appended to `bracket.tsv`.
7. Tier: C (pending release) for a bracket result; B (kept, `gzip -n` in place, verified) for anything that stops the batch.
8. Release, if a records repository is configured (§9).

### 5.3 Estimates (not invented)

The per-run raw size and wall-time limit are **inputs, not defaults**: `S5_E0VN_RUN_BYTES` and `S5_E0VN_RUN_LIMIT_S`.
- The executor derives them from the accepted N = 2 smoke record (its size and wall time) and the plan's sizes (plan §2.1: 0.5–1.2 GB per E0v-N run; §4.3 totals).
- The values are recorded in `env-e0vn.txt`.
- The maintainer reviews them with the authorisation (§10, EG-1).
- The runner refuses to start without them.

## 6. f_E1 selection and verification

### 6.1 Selection (S-1, S-2; S5-2-D4)

`m2s72s5n.sh select` (no simulation) reads the **committed** bracket records of both segments. It requires:
- every one of the 49 combinations bracketed, each with exactly the declared start factor;
- no record of any other combination.

f_E1 = the largest ladder factor ≤ (1 − 0.20) × min f_lo over all 49 combinations.

Reported:
- the binding combination;
- f_E1 for m = 0.10, 0.20 and 0.30.

A combination without f_lo, or no ladder factor below the limit, is **STOP (exit 8): no fallback** (RD-2). The record `fE1-selection.txt` is never overwritten.

### 6.2 Not part of this batch

E1 itself. E2 (re-declared later, plan §2.6).

### 6.3 Verification (E1 entry gate; declared here, executable only after A4)

Every E1 loaded configuration is run at f_E1, with seeds 0–4. Checks V-1 … V-4 apply per run and per UE (`m2s72_e1sel.verify_run`, unchanged). Any failure stops E1 and is reported: no automatic lower factor.

**Dependency.** The E1 configurations do not exist yet: the generator's E1 section is work package A4. Until A4 is accepted, f_E1 remains a candidate, and **E1 does not start**.

### 7.1 Execution modes (161-R1)

| `S5_E0VN_MODE` | Behaviour |
|---|---|
| `production` | Genuine execution. Refused while any test hook is set, with a substituted evaluator, or before AG-1 is approved. The build always runs. Stage names `M2-S7.2a-e0vn-<h16\|h5\|select>`. |

- its stage and destination names differ;
- its environment record says TEST;

## 8. Failure and stop conditions

| Exit | Condition | Evidence |
|---|---|---|
| 0 | segment complete: every combination `bracketed` or `top` | all tier C (released if a records repository is set) |
| 1 | a precondition of §7 refused | nothing created |
| 3 | free-space rule before a run | nothing deleted; the run did not start |
| 5 | a simulation outcome SIM-ABORT / TIMEOUT / ERROR, or a manifest failure | the run: tier B, recorded `invalid` |
| 6 | wrapper exit 1 FAIL, 2 REFUSED / EVALUATION ERROR, 3 HELD FOR REVIEW, 4 INCOMPLETE; a digest that fails the completeness check; a record the state machine refuses | the run: tier B, recorded `invalid` |
| 7 | release failure (records not committed or not verified in HEAD) | raw outputs kept |
| 8 | a bracket `non-monotone` or `below ladder`; a HARQ5 start impossible; f_E1 selection STOP | the batch's records |

**Every stop is for review.** A batch is never resumed into the same stage directory. A repeat needs a new results root and is recorded as such.

**Tiers (plan §4.2):**
- **A (committed):** every file under `records/`, copied recursively to `simulations/results/simu5g-1.8.1/s5/<root>-<stage>/` of the records repository (`S5_RECORDS_REPO`), committed and verified blob-by-blob in HEAD.
- **B:** the raw outputs of a run that stops the batch: kept, `gzip -n` in place, verified against the manifest.
- **C:** every other run's raw outputs, deleted **only after** tier A is verified, each against its manifest. Deletions are recorded in the ledger.

Without a records repository nothing is deleted.

**No accepted record is written or overwritten:**
- the runner writes nothing under `simulations/m2/results`;
- the stage directory is never reused;
- the records destination must not exist when the batch starts.
