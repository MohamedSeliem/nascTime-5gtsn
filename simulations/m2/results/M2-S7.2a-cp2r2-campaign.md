## 3. Rule added for item 9 (end-of-run vs discard)

**EOR**, per run and DS-TT k, with the same rule for every configuration. Every GM Sync and Follow_Up (domain 0) is classified as exactly one of:
- **delivered:** received on DS-TT k `eth[0]`;
- **end-of-run:** not delivered, and its GM first bit + L_max > T_end, where L_max is the largest GM-first-bit → DS-TT-k-arrival latency among the frames delivered to DS-TT k in that run;
- **LOST:** anything else.

PASS iff LOST = 0 and no delivered frame is absent from the GM.

The DS-TT egress end-of-run states are I-2H rule 8 (unchanged). F0-1's cohort rule is unchanged.

**Reported, not gated:** the RLC PDU accounting of the loaded UE (UE 1) in Block H16. Inferred MAC deletions = gNB RLC PDUs handed to MAC at t ≤ T_end − 4 ms that never reached the UE's RLC (UM, no ARQ). MAC deletions themselves are not recorded by these configurations; P1 observed them directly in scratch runs.

## 4. Item 8: the secondary holdTimeout message

These are message-text changes only, and verdicts are unchanged.
- The I-2H parser now ends a hold at `holdExpired`. This removes the spurious "hold of 22 while hold of 21 active". Any log containing `holdExpired` already fails rule 1, so no verdict changes.
- The message for a Sync without a `syncTx` row now says that an expired hold removes the Sync from the pending set (TtSyncEgress::release(true)). The Sync is still transmitted on the wire, so the earlier wording "never transmitted" was misleading.
