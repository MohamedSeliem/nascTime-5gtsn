## 2. What was implemented, against the F2 requirements

1. **Lifecycle attribution** (`replay`):
   - **Handles.** A handle is bound per lifecycle by rules B-1…B-6. It is created at the first unique NACK and retired at ACK or discard. A retired handle that reappears, or a bound handle that is not among the group's candidates, is A2-1 FAIL. A new lifecycle on the same key starts unbound.
   - **Multi-NACK groups.** These keep the handles AMBIGUOUS over the set of lifecycles. The lines are `exchangeable-nack`. Ambiguity is narrowed only by elimination: a later unique resolution, or a bound handle.
   - **Mixed groups.** These are PENDING and are resolved, in log order, by each candidate's first main-loop event on its key: an extract of its own MAC id means it was retransmitted; an insert means its unit was emptied. Assignments keep the group's original line index and time.
   - **Groups that counts already decide.** When a group has no RTX line, or has only RTX lines, its outcome is closed by counts at once.
   - **Discards.** A discard is resolved by a bound handle, then by eligibility (`ntx = maxHarqRtx + 1`). Otherwise it is UNRESOLVED, which is A2-1 FAIL.
   - **Structural censoring.** A NACK or pending group is censored only when no complete main loop follows it in log order. Otherwise, or when the log has no markers, it is UNRESOLVED, which makes A2-9 NOT EVALUATED and the verdict INCOMPLETE.
2. **ACK-only invariance.** On ACK-only input every frozen row except A2-4 has an identical status and an identical detail, and the per-UE output is identical. When A2-1 fails on ACK-only input, the frozen message is kept.
3. **Shared probe.** P0 is computed from the same replay as A-2.1, in the frozen report format. P0-4 is split into P0-4a and P0-4c when there are retransmissions. The frozen `m2s72_a2probe.py` is unchanged.
4. **A2-4 split into three separately reported rows:**
   - **A2-4a.** Each retransmission must have a "selected for retransmission" line for its process in its TTI under the MAC, and each such line must have a retransmission.
   - **A2-4b.** On the UE side, the retransmitted MAC id is received by the same node: after the transmission and before the next one. No fixed delay is assumed. The row is NOT EVALUATED without UE lines.
   - **A2-4c.** The `rtxAcid` line under `mac.schedulerDl` must name the node and the process. It is **NOT EVALUATED** when the log has no scheduler line, with the reason taken from the `.sca` log-level configuration when one is available. It is never PASS by absence.
5. **No universal one-TTI UE delay.** A2-4b uses ordering only. The test T-a24 checks it with UE feedback delays of 2 and 3 TTIs.
6. **XA independence.** UE-side evidence never resolves a gNB attribution. It is used only by A2-7 and A2-4b.
   - When XA itself cannot separate a line that A-2.1 resolved uniquely (two UEs, same process, same time, same result), A2-7 checks only the group multiset. That line is counted as "reference ambiguous", not as confirmed.
7. **FAIL versus INCOMPLETE versus NOT EVALUATED:**
   - any FAIL gives NOT VALID (rc 1);
   - a required row that is neither PASS nor NOT EXERCISED gives INCOMPLETE (rc 4);
   - contract `full` requires A2-4c, so without scheduler logging the best possible verdict is INCOMPLETE;
   - contract `f1d-i` (the supplementary post-hoc validation approved as F1-d (i)) does not require A2-4c.
8. **Fixtures:**
   - a synthetic reconstruction of the first real chain;
   - corrected synthetic fixtures;
   - lifecycle and ambiguity regressions;
   - the declared controls (§4).
   - The real-chain fixture slot is pinned by sha256 and is PENDING; see §6, L-1.
9. **Baseline guard on negative controls.** Every declared row of a negative control must be PASS before the mutation; otherwise the control is NOT BUILDABLE and never counts as a pass. After the mutation, a declared row must FAIL. Where a token is declared, the FAIL detail must name the mutated element.

## 5. Real chain: synthetic reconstruction (T-recon-first-chain)

The reconstruction is built from the facts reported from the VM and is labelled synthetic:
- node 2050, MAC id 145933, handle 54326, process 0;
- transmission at 361 ms;
- NACK at 366 ms, in the same group as node 2049's ACK;
- retransmissions at 367, 373 and 379 ms; NACKs at 372 and 378 ms;

A-2.1 resolves it as follows:

- the 372 and 378 ms NACKs are `bound`;

## 6. Limitations and deviations from F1 revision 2

- **L-1. The real-chain fixture is pending.** `check/fixtures/a2v1-first-chain.log.gz` and its `.sha256` pin are not in the repository: extracting them reads the sealed A2-V1 output on the VM, which is outside this stage. T-real-first-chain reports PENDING, never PASS, until both files are added, and then runs the same assertions as T-recon-first-chain.
- **L-2. P0 now comes from the shared replay (F1-b).** A-2.1 does not use the frozen probe's independent state machine. The frozen probe stays as it was for the frozen A-2.
- **L-3. Row set.** A2-4 is replaced by A2-4a, A2-4b and A2-4c, and A2-9 is new. All other rows keep their frozen definitions on ACK-only input.
- **L-4. A2-7 and reference-ambiguous lines.** This is a precision added during implementation. When XA cannot separate a line that A-2.1 resolved uniquely, the line is checked only by group multiset and counted separately, not as confirmed. XA still never resolves an attribution.
- **L-5. Groups closed by counts.** These are added explicitly: a group with no RTX line, or with only RTX lines, is closed at once rather than waiting for key events. This is the "counts close the group" rule of rev. 2 §3. Without it, a joint discard-plus-ACK group would wait forever and end as INCOMPLETE instead of the specified A2-1 FAIL "UNRESOLVED discard".
- **L-6. A2-4b censoring.** A retransmission whose UE reception falls after the last UE line is censored, not failed.
- **L-7. A2-8 is not required by either contract,** as in the frozen A-2. It still makes the verdict NOT VALID when it FAILs.
- **L-8. NC-A21-dropfb declares no token.** A removed event shifts the attribution of the next event on that process, so the A2-2 detail may name a neighbouring PDU. The control is still guarded by the baseline rule.
- **L-9. Not implemented here:** the adapter that runs A-2.1 post hoc on the sealed A2-V1 output. Both its execution and the fixture extraction need separate authorisation.
