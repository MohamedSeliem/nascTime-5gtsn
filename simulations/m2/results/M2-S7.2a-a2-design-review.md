Module context is the gNB MAC (`M2S72Bridge.gnb1.cellularNic.mac`) unless stated otherwise. Level is EV (info), captured by the existing `M2S72-MACLOG` configuration. Prefix `"%t|%M|"`.

| Event | Line (source) | UE node | PDU id | Result | In N = 1 / N = 2 logs |
|---|---|---|---|---|---|
| new PDU into unit | `H-ARQ TX: new pdu (id X ) inserted into process p codeword id: c for node with id n` (`LteHarqBufferTx.cc:131`) | **yes** | **yes** | — | yes |
| every transmission (first and each retransmission) | `\t H-ARQ TX: pdu (id X ) extracted from process p codeword c for node with id n` (`:242`) | **yes** | **yes** | — | first transmissions only |

| UE k reception | `H-ARQ RX: new PDU (id X ) inserted into process p` (`LteHarqBufferRx.cc:63`; module `ue[k].cellularNic.nrMac`) | **yes** (module) | **yes** | — | yes |
| UE k feedback sent | `H-ARQ RX: feedback sent to TX process p Codeword  c of node with id g result: R` (`:78`) | **yes** (module) | no | yes | yes |

**Source facts that fix the semantics:**
- One TX buffer per UE (`LteMacBase.h:36`); lowest free process (`LteHarqBufferTx.cc:137`).
- A feedback is checked against the PDU id in its unit and the simulation aborts on a mismatch (`:190-200`). A feedback therefore always closes or re-arms **the** PDU of its unit.
- NACK → unit BUFFERED (`LteHarqUnitTx.cc:140`). After `maxHarqRtx + 1` transmissions a NACK discards the PDU (`:124-136`; default `maxHarqRtx` 3, `LteMacBase.ned:37`).
- A retransmission sets `txTime_` and the transmission count (`:88-90`) and is logged as an `extracted` line with the same PDU id.
- The MAC PDU id survives the air (`LteMacPdu.msg:134`, `:143`). An air frame lasts one slot and is delivered at its end (`PhyBase.cc:120`, `:214`).
- Simu5G attributes every feedback internally: the event's source node selects the buffer (`LteMacBase.cc:124`). It emits per-UE statistics **on the UE's MAC** at that moment: `harqErrorRateDl` (0 / 1 per feedback), `harqTxAttemptsDl` (transmissions of each ACKed PDU), per-attempt error rates, `macPacketLossDl` (`LteHarqUnitTx.cc:165-195`). In the E0v / E0v-N configurations only their **`:mean` scalars** are recorded (`record=mean,vector`, `**.vector-recording = false`).

**Consequence (the key observation of this review):**
- Every DL H-ARQ event **except an ACK** is identified in the gNB log, by PDU id (NACK, discard, transmission) or by UE node (insert, transmission, rtx scheduling).
- An ACK is anonymous, but it is the only feedback of its unit at that instant.
- Two anonymous ACKs at the same (t, process, codeword) with the same age close two units with identical outcomes. Which line closes which unit can matter only if another event of one of those UEs lies between the two lines, and that is checkable (§5.6).

### 3.1 New finding: A-1 misattributes after a NACK; it does not only orphan

On the source-faithful generator (`m2s72_harqfix.make`, N = 2, one 4-transmission discard chain and two single NACKs over 400 TTIs):
- A-1 attributes **184 lines to the wrong UE as A-1a**;
- only **5** lines surface as ORPHAN.

PU-4 still FAILs, because orphan > 0, so A-1 stays fail-closed at the run level. But its per-line A-1a output after any NACK is not trustworthy. The XA reference measures exactly these 184 disagreements (test). The N = 2 protocol's F-4 wording ("becomes ORPHAN (or is misattributed)") understated this.

**Sweep (48 scenarios, §6.4):**

| Scenarios | Feedback lines | A-1 wrong | A-1 unresolved |
|---|---|---|---|
| 16 NACK-free | 13,937 | **0** | 2,298 (exactly the exchangeable groups) |
| 32 with NACK sampling (757 NACKs) | 27,793 | **557** | 5,741 |

**Conclusion:**
- A-1 is a correct but incomplete rule **only in the absence of NACKs**.
- Two things are needed:
  1. a rule that is complete under simultaneous feedback;
  2. a rule that models the unit's retransmission state.

  XA has both properties, but it is the wrong thing to promote, for the reason in §4.

## 5. A-2 specification (gNB-only unit-state attribution)

### 5.1 Assumptions

Each assumption is checked on every run; a violation fails closed.

| # | Assumption | Basis | Run-time check |
|---|---|---|---|
| G-1 | one TX unit per (UE node, process, codeword); a new PDU enters only an empty unit | `LteMacBase.h:36`; `insertPdu` throws otherwise (`:117-124`) | A2-2 (no insert into an occupied unit) |
| G-2 | every transmission is logged once with PDU id and node (`extracted`) | `sendSelectedDown` (`:236-245`) | P0-2 / A2-2 |
| G-3 | each feedback event logs one block: start, one unit outcome, the feedback line; NACK and discard outcomes carry the PDU id | `:173-224`, `LteHarqUnitTx.cc:104-160` | P0-1 / A2-1 |
| G-4 | the feedback of a transmission arrives d*_tx after it, one constant per run | PHY slot timing, UE `harqFbEvaluationTimer` (`LteHarqProcessRx.cc:78`) | P0-3 / A2-3 (single value, every attribution) |
| G-5 | log order = event order of the gNB MAC module | Cmdenv writes EV synchronously | implied by the checks; R-ELOG for 0–0.5 s |
| G-6 | a retransmission is scheduled for the node and process the scheduler names | `LteSchedulerEnbDl.cc:108`, `:270` | P0-4 / A2-4 |
| G-7 | no handover, D2D, dropped units or feedback-to-other-PDU | single cell, no D2D; out-of-scope texts | P0-6 (text absent) |
| G-8 | Simu5G 1.8.1 texts as cited | source | contract tests against the VM's own `$SIMU5G_ROOT` |

**Not assumed (unlike A-1):**
- no NACKs;
- one UE per process;
- feedback within a fixed delay of the **insert**: the delay is measured from the last **transmission**, so retransmissions obey the same d*_tx.

### 5.2 State and transitions

The state is replayed in log order, gNB module only. Unit key u = (node, p, cw), holding {PDU id, state, last_tx, n_tx, t_insert}.

| Line | Transition | Fails closed when |
|---|---|---|
| insert(X, p, c, n) | u := INSERTED(X) | u occupied |
| extracted(X, p, c, n) | INSERTED/BUFFERED → WAITING, last_tx := t, n_tx += 1 | u holds no X, or u is WAITING |
| unit "set for RTX X" in a feedback block | (resolved with the group, §5.3) → BUFFERED | X is not a candidate |
| unit "discarded X" in a feedback block | → closed (HARQ residual loss) | X is not a candidate; n_tx ≠ maxHarqRtx + 1 |
| feedback(p, c, ACK) | → closed (§5.3) | no candidate / count mismatch |
| rtx scheduler lines | evidence for the next retransmission extract of (node, p) | missing (A2-4) |
| end of log | WAITING with last_tx + d*_tx > t_end, or INSERTED in the last TTI: **censored**; anything else open: failure | — |

### 5.3 Attribution of feedback lines

**Groups.**
- At a feedback line (t, p, c), the **candidates** are the WAITING units on (p, c) with the largest age t − last_tx. That age must equal d*_tx. No WAITING unit can be older, because its feedback would already have arrived (G-4).
- All feedback lines with the same (t, p, c) form one **group**. Its candidate set is fixed at its first line.
- Lines of different groups may interleave within one feedback burst. This was found by prototyping at N ≥ 3: the generator interleaves different processes in one burst.

**Resolution.** A group is resolved **as a whole**, when its burst ends (time advances, or a main-loop insert / extract occurs):
1. **NACK / discard lines** are resolved by the PDU id of their own unit line. Result class **id**.
2. The remaining ACK lines are matched to the remaining candidates:
   - 1 : 1 → class **single**, exact;
   - k : k with k ≥ 2 → class **exchangeable**: an arbitrary bijection, valid by §5.6;
   - any other count → failure (a lost or extra feedback).

**Calibrating d*_tx.** d*_tx is learned as the age of the oldest candidate. It must be **one value per run**; otherwise A2-3 fails and nothing is evaluated per UE.

### 5.4 Per-UE outputs

Never gates; reported only when every A2 gate passes:
- inserts and transmissions;
- feedback lines (ACK / NACK);
- transmissions per PDU (histogram);
- discards (HARQ residual loss);
- HARQ latency per PDU (insert → final ACK);
- feedback age (≡ d*_tx);
- open at end (censored);
- **occupancy** (§5.5).

### 5.5 Per-UE occupancy

A process of UE k is **busy** from its insert line to the line that empties the unit: the ACK line of the PDU's final feedback, or its discard line. A NACKed (BUFFERED) unit **stays busy**: it holds the process, which is exactly why Simu5G cannot reuse it.

The histograms are those of `m2s72_peru.occupancy_log_order` (unchanged): busy count at the start of each TTI, and peak within each TTI, over the measurement window. A-1 cannot give this; it closes the process on a NACK.

### 5.6 Exchangeability (why anonymous ACK groups are exact)

**Claim.** Consider a group of k ACK lines at (t, p, c) with candidate set C, |C| = k, all of age d*_tx. Every bijection lines → units gives:
- the same per-unit outcome (each unit ACKed at t, with its own n_tx and insert time);
- hence the same per-UE feedback count, NACK count, n_tx histogram, latency multiset and age.

The per-UE log-order occupancy differs between bijections **only if** some insert, extract or close of a candidate's node lies strictly between the group's first and last line, other than the group's own closes.

**Proof sketch.**
- The per-unit outcome is a function of the unit and the result, and every line carries the same result ACK at the same t.
- Occupancy of node n changes by −1 at the line that closes n's unit. Permuting the closing lines inside the group moves those −1 steps only within [first, last].
- The at-TTI-start count is unaffected, since all lines share one TTI. The within-TTI peak is unaffected unless a +1 step of n lies inside that interval.

**Certificate (checked per group, A2-5):** no such event inside the interval. On violation, A-2 reports the group as not certified and that TTI's peak as NOT EVALUATED. It never guesses.

Exact, per run; each is a gate of A-2's per-UE evaluation:

### 5.8 Generality and scope

**In scope:**
- any N;
- k-way groups (k ≤ N);
- HARQ 5 and 16;
- codeword-aware (the gNB lines carry c). The UE-side reference XA only covers codeword 0 (its RX line has none).

**Out of scope, each fail-closed:**
- MIMO "jumbo TB" merging of codewords on retransmission (`LteHarqBufferTx.cc:74-95`: one codeword's PDU absorbs another's, and the absorbed one is dropped without a feedback line). Detected as an A2-2 failure: a unit open without a feedback.
- Handover, D2D, dropped units (P0-6).
- UL: the same machine applies to the UE-side TX logs, where the module names the UE (later).

**HARQ-5 MAC deletion ("no available process", `LteMacEnb.cc:585`):** no insert line, so no unit. Q8-v keeps covering it (unchanged).

**MG-1 interplay:** MG-1 will count a real `discarded (max retransmissions reached)` line as UNCLASSIFIED loss-like, because "discard" matches `m2s72_maclog.LOSSY`. That is a correct fail-closed outcome under the current grammar. Classifying it is a separate MG-1 revision, tied to A-2 adoption (A2-D1).

### 6.4 Design evidence produced here (synthetic; labelled as such)

`proto_m2s72_a2.py` sweeps **48 scenarios** with the generator, against its truth:
- N ∈ {2, 3, 4};
- HARQ ∈ {16, 5};
- feedback burst before or after the main loop;

- every single-candidate ACK correct;

**Two defects were found while prototyping and fixed in the design** (both recorded as mutation controls M5 and M6):
1. resolving a group line by line instead of as a whole;
2. closing a group at a feedback line of another process.
