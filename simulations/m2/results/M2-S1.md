# M2-S1: complete observed 5G–TSN bridge residence interval (results)

**Verdict: PASS.** All 28 rows of `M2-S1/check.txt` pass. The M2-S0 and M1 regressions are unchanged (Regressions section).

**Main finding:** for every frame, in both directions, nascTime measures the complete observed bridge residence interval:

> **R = t12 − t1**: from the last bit received on the ingress translator's TSN port to the last bit sent on the egress translator's TSN port.

- **Inputs.**
  - **t1:** the M2-S0 tag.
  - **t12:** the transmitter's `transmissionEnded`, paired to the frame by tree id, FIFO order and payload hash.
- **Verification.** R equals PCAP to the picosecond.
- **Decomposition.** R splits into measured intervals at both translators plus the 5G-system block, each verified independently and with no double counting.
- **No side effects.** Wire, QoS mapping and clock behaviour are bit-identical with the instrumentation on or off.

**Wording.** R is an *observed interval between two port events*. It is **not** an IEEE 802.1AS residence time or a transparent-clock correction. Nothing is written into any frame, `correctionField` is untouched, and no synchronization-accuracy claim is made.

## Events and intervals (as approved, with the deviations below)

| Event | Where | Observed by |
|---|---|---|
| **t1** ingress | TT_in `eth[1]` `receptionEnded` (last bit received) | Tag `ingressTime`; must equal the `receptionEnded` time of the same tree id (C2) |
| t2 / t3 / t4 / t5 | TT_in `eth[0]`: MAC FIFO entry / MAC dequeue / `transmissionStarted` / `transmissionEnded` | Observer layer on `eth[0]` (tag still on the frame) |
| t6, t7 | 5G-system Ethernet ports (UPF `dnEth`, UE `eth[0]`) | PCAP only (5G system not instrumented) |
| t8 | TT_out `eth[0]` `receptionEnded` (end of the M2-S0 partial interval) | Observer layer on `eth[0]` |
| t9 / t10 / t11 / **t12** | TT_out `eth[1]`: MAC FIFO entry (M2-S0 callback) / dequeue / start / **`transmissionEnded` = final egress** | Egress processor; tree id + FIFO + payload hash |

**Intervals** (half-open, telescoping):

| Symbol | Interval | Meaning |
|---|---|---|
| P_in | t2 − t1 | TT_in processing |
| Q_in | t3 − t2 | TT_in MAC FIFO, including the inter-frame gap |
| G_in | t4 − t3 | TT_in dequeue to transmission start |
| X_in | t5 − t4 | TT_in transmission |
| B | t8 − t5 | 5G-system block |
| P_out, Q_out, G_out, X_out | t9 − t8, t10 − t9, t11 − t10, t12 − t11 | The same four intervals at TT_out |

`B` is independently cable (50 ns) + S (5G port to 5G port) + cable (50 ns), from PCAP.

**Processing intervals are measured, not assumed:**
- P_in = FIFO entry at TT_in `eth[0]` − t1.
- P_out = FIFO entry at TT_out `eth[1]` − the `receptionEnded` that delivered the frame.

On every frame that found its port idle, PCAP gives P independently as (PCAP out − (L + 8) · 8 ns − PCAP in on the other port). That covers 10 540 of 10 714 frames at TT_in and 10 294 at TT_out. In the pass-through configuration P is measured as 0 on every frame, and the PCAP value agrees on every idle-port frame.

## Safeguards requested at approval

1. **Unique pairing across the transmission signals.**
   - A frame whose tree id is already pending on the port is rejected when it enters the MAC FIFO.
   - Each event (dequeue, start, end) must match exactly one pending record, be the oldest record lacking that event, follow dequeue < start ≤ end, and (for the end) be the FIFO head.
   - At the end of transmission, the transmitted payload hash and tag presence must equal those recorded at enqueue.
   - Any orphan, ambiguous (shared tree id), duplicate or out-of-order event, any bit-error or aborted transmission, and any MAC-queue drop of a recorded frame stops the run with an error. The pairing self-test covers each rule, including a shared tree id both at enqueue and at event time.
   - Independently, C4 re-pairs every row against PCAP by transmission position and payload hash.
2. **Wording:** "complete observed bridge residence interval" throughout, with no IEEE 802.1AS / transparent-clock claim (see the main finding).
3. **Processing intervals measured, zero verified independently:** see the "Processing intervals are measured" paragraph above, and row C6.

## Deviations from the approved design (`migration/m2-s1-design.md`)

| Design | Implemented | Why |
|---|---|---|
| G = "inter-frame-gap hold" after the MAC dequeue; Q = MAC queueing only | **Q includes the inter-frame gap; G (dequeue → start) is 0** | INET 4.7's `InterpacketGapInserter` enforces the gap by back-pressure: it refuses frames until previous end + 96 ns (`InterpacketGapInserter.cc:109–120`), so the MAC server dequeues exactly at transmission start. Found by C6 on the first run, which logged t3 = t4 = previous end + 96 ns. The PCAP model (start = max(arrival, previous end + 96 ns)) is unchanged and exact; only the split between Q and G was predicted wrongly. |
| Egress observation on TT_out `eth[1]`; separate observer only implied | Observer layer (mode `"observer"`) on both translators' `eth[0]` as well, giving t2–t5 and t8 per frame by frame id | Needed for the measured TT_in intervals and B |
| Pairing self-test "extended to synthetic event sequences" | 10 cases, written to the port log (not the M2-S0-format log) | Keeps the M2-S0-format logs byte-identical (C15a) |
| Negative-control signatures | Checked exactly per frame by the checker (not only the failing-row set) | Stronger evidence |
| — | C15a: M2S1 runs reproduce the M2-S0 recorded PCAP files and logs byte for byte | Direct evidence that the M2-S0 behaviour is preserved with the instrumentation on |

## Limitations (from the design, confirmed or unchanged)

- **Observation relies on INET 4.7 signal semantics:**
  - `transmissionStarted` / `transmissionEnded`, `receptionEnded`;
  - the MAC emitter's `packetSentToLower`;
  - back-pressure inter-frame-gap enforcement.

  Unsupported cases stop the run: preemption, cut-through, aborted or bit-error transmissions, and MAC-queue drops of recorded frames.
- **PCAP is an independent observer, not an independent clock.** Simulation time only.
- **The 5G system is not instrumented.** S is known from PCAP at its Ethernet ports only.
- **Last-bit events (PCAP-consistent).** A first-bit residence would be equal here only because both TSN links run at 1 Gb/s and frames leave byte-identical. This is not the IEEE 802.1AS timestamp point.
- **Single configuration:** one gNB and one UE, numerology 0, M1 traffic, TSN-side translator queues far from saturation.
