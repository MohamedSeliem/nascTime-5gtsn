**A-2's comparison.** The frozen A-2 resolves a NACK by `units[k]["pid"] == line["block_pid"]` (`m2s72_a2.py:136`, with `block_pid` from the unit line at `:238-240, 299`). The left side is a MAC PDU id, the right side a cMessage id. The two counters are independent, so the comparison is **never true for a real NACK**, except by coincidence.

The frozen probe (A2-0) makes the same comparison (`m2s72_a2probe.py`, NACK branch: "NACK for PDU … not an oldest awaiting unit").

**Why every synthetic test passed.** The generator `m2s72_harqfix.make()` writes the unit line with the **MAC id** (`… PDU {x} set for RTX`; `m2s72_harqfix.py:96`). The injected chain of `a2-controls` does the same (`check_m2s72_a2.py:197`). The source-faithfulness of the generator was checked for the log **texts** (A2-0s), never for the **identifier namespace** inside them. This is a test-design gap, and the correction closes it (§7).

**What is stable.** Within one H-ARQ unit, the handle `H` is constant (CONFIRMED by source):
- `pdu_` is set once in `insertPdu` (`LteHarqUnitTx.cc:56`) and released only by `resetUnit` (after an ACK or a discard);
- each transmission sends a **dup** (`extractPdu`, `:99`), so `pdu_` keeps its id;
- every NACK and the final discard of a unit therefore print the same `H`.

## 3. Can gNB-only evidence resolve mixed ACK/NACK groups? (CONFIRMED for the cases below)

**Facts (source).** One TX buffer per UE (`HarqTxBuffers`, `LteMacBase.h:36`), so a unit key is (node, process, cw). After a feedback group G at time t:
- a **NACKed** unit is BUFFERED and its next event can only be its **retransmission**: an extract of **the same MAC id** on the same key (`rtxschedule` → `markSelected` → `sendSelectedDown`). An insert into a non-empty unit throws (`LteHarqBufferTx.cc:122-123`), so no insert can come first. The discard path empties the unit instead (no rtx).
- an **ACKed or discarded** unit is EMPTY. Its next event on the key can only be a **new insert**, and never an extract of the old MAC id.

The **first gNB main-loop event on a candidate's key after G** therefore determines its outcome: "rtx-proven" (NACK) or "emptied" (ACK or discard). This needs neither XA nor the cMessage id.

`rtxAcid` (`LteSchedulerEnbDl.cc:108`: `User[node] … ACID [p]`) corroborates as before (A2-4), but is not needed for resolution.

**Counting closes most groups early.** With n_R `set for RTX` lines in a group, the group is resolved as soon as n_R candidates are rtx-proven: all the others are emptied. Most groups therefore resolve one TTI after G, at the retransmission, without waiting for an insert that may come much later.

**Limits (fail-closed, §6):**
- A group still unresolved at the end of the log is censored.
- **Discard versus ACK** among emptied units: emptied units cannot be told apart by later events. They are resolved by:
  - (a) a handle already bound to a unit (§5); or
  - (b) eligibility: only a unit with ntx = maxHarqRtx + 1 can be discarded, so if exactly n_D emptied candidates are eligible, they are the discards.

  Otherwise the group is **UNRESOLVED**, which is a failure.
- ≥ 2 NACK lines in one group: the NACKed set is resolved, but the line ↔ unit (handle) binding among them is exchangeable. It is left unbound and only matters for a later discard. A2-V1 cannot produce this case (ue[0] `perDl` = 0); synthetic tests cover it.

## 4. Mapping between cMessage (Packet) ids and MAC PDU ids

**CONFIRMED by source: no log line carries both.**
- The unit stores both (`pdu_` and `pduId_` = the MAC id, `LteHarqUnitTx.cc:56-57`), but prints only the cMessage id.
- The feedback carries `fbMacPduId` (`LteHarqFeedback.msg:28`), which is printed only on the mismatch path, and that path throws (`LteHarqBufferTx.cc:193-200`).
- The scheduler and the MAC print no message ids for H-ARQ.
- The two counters are independent: no numerical relation may be assumed.

**The only reliable link** is evidential: a handle H printed in a group whose NACKed unit is identified (single candidate, or rtx-proven, §3) is bound to that unit's MAC id. Because H is constant per unit, every later NACK or discard line with H then identifies its unit directly. Two consistency rules apply:
- a handle may bind to one unit only;
- a unit may carry one handle only.

Any violation is a FAIL. If an implementation ever met it, it would contradict the source.

## 5. Why `NC-V-rtxacid` was NOT BUILDABLE (OPEN; source facts CONFIRMED)

**Source facts:**
- `rtxAcid - Node [g], User[n],  Codeword [c]  of [k] , ACID [p] ` is printed **unconditionally** at the start of `schedulePerAcidRtx` (`LteSchedulerEnbDl.cc:108`).
- That function is the only DL retransmission path: it is called from `rtxschedule` (`:302`), which `scheduleRetransmissions` calls whenever a DL process awaits retransmission (`LteScheduler.cc:100-114`).
- `NOW` is printed **without a space** before the text. `MacNodeId` prints as a plain number (`LteTypes.h:46`).

The probe's `R_RTXACID` matches that exact text, and `rtxAcid` is in A-2's `KEYWORDS`. So the retransmissions at 367 / 373 / 379 **must** have produced such lines, naming the gNB node and `User[2050]`.

The control is built by `_first(lines, gNB line ∧ R_RTXACID ∧ User == node_id[1])`. It was NOT BUILDABLE, so that predicate matched **no** line of A-2's input.

**Hypotheses (one read-only command decides; §8 step 2):**

| Id | Hypothesis | Prediction | Consequence |
|---|---|---|---|
| H-a | the lines are absent from the run log | `zgrep -c "rtxAcid - Node"` = 0 | contradicts the source as read. Check the scheduler class in use (a different DL scheduler module). **A2-4 FAILs independently** (C-3) |
| H-b | present, but `User[…]` is not `node_id[1]` (e.g. the LTE-leg id or another id) | the count is > 0 and the User values differ from the insert lines' node | the rtx evidence names a different id space. A2-4's node match fails (C-3); the correction must map ids (source-backed) or fail closed |
| H-c | present and matching, but not in A-2's input | count > 0 in the raw log, 0 in `A2.load` | a filtering defect (prefix / module mismatch) |
| H-d | present and matching, but the evaluator's predicate is wrong | found by a direct `R_RTXACID` scan of `A2.load` | an evaluator defect only (control construction); A-2 is unaffected |

**Resolution.** H-a/H-b affect A-2 (A2-4) and must be fixed or explained before the correction is final. H-c/H-d are fixed where the defect lies.

## 7. Minimal correction (A-2.1): fail-closed attribution algorithm

**Scope.** These files change only in their NACK / discard branches:
- `m2s72_a2.py` (`finalize`, group handling, main-loop resolution);
- the probe's NACK branch, which shares the same helper (so A2-0 cannot disagree with A-2);
- the generator `m2s72_harqfix.make()`: a separate handle counter for unit lines; retransmission in the TTI after the NACK (a parameter, default the observed behaviour);
- the `a2-controls` injection: the handle namespace.

**Unchanged:**
- the ACK-only paths: single candidate, exchangeable groups, the certificate, ages, censoring, every row definition, every gate, A2-7 / A2-8;
- XA, A-1, PU-4 and the adapter.

**Versioning.** A-2.1 is a **new version tag** in every output. The frozen `fbee202` A-2 stays callable for reproducing the original verdict.

**State.** A unit key is (node, p, cw), with `mac_id`, `ntx`, `st` ∈ {INS, WAIT, BUF, **PEND**} and `handle` (None or an int). Handle table: `H → unit`.

**Group G** = lines at the same (t, p, cw). The candidates C are the WAIT units of (p, cw) with the oldest last transmission, as now. Line kinds: ACK, RTX (`set for RTX`, handle H), DISC (`discarded`, handle H).

1. **Bound handles.** Each RTX / DISC line whose H is bound to a unit u is assigned to u. If u ∉ C, or u is not WAIT → **A2-1 FAIL** ("bound handle outside candidates").
2. **Count.** Let C', L' be what remains. If |C'| ≠ |L'| → **A2-1 FAIL** (unchanged).
   - If |C'| = 1: assign; bind H if it is an RTX / DISC line. If the unit already has a different handle → **A2-1 FAIL**.
   - If every line of L' is ACK: the existing single / exchangeable path (certificate unchanged).
   - Otherwise (mixed, or ≥ 2 RTX): **PENDING**. The units of C' go to PEND (busy; not candidates of later groups).
3. **Resolution of a PENDING group** by the first main-loop event on each PEND unit's key:
   - an **extract of its own `mac_id`** → rtx-proven (state BUF → transmission, as for a resolved NACK);
   - an **insert** → emptied;
   - an extract of another MAC id on the key → **A2-2 FAIL**.

   Once the number of rtx-proven units reaches n_RTX (L'), every other unit is emptied. Once the number of emptied units reaches n_ACK + n_DISC, every other unit is rtx-proven. More rtx-proven units than n_RTX, or more emptied than n_ACK + n_DISC → **A2-1 FAIL**.
4. **Line assignment after resolution:**
   - RTX lines ↔ rtx-proven units: with 1, bind H; with ≥ 2, exchangeable (no binding; recorded).
   - DISC lines ↔ emptied units: first bound handles, then the units with ntx = maxHarqRtx + 1 if their count equals n_DISC; otherwise **A2-1 FAIL (UNRESOLVED)**.
   - ACK lines ↔ the remaining emptied units: single, or exchangeable with the unchanged certificate.
   - Owner, ntx and age are written to the lines.
   - The −1 occupancy events of the emptied units are placed at their assigned line's gNB index (`busy` is sorted by index). RTX units stay busy.
   - Line class: `bound`, `single`, `resolved-by-rtx` or `exchangeable` (the old `id` class disappears).
5. **End of the log.** A PENDING group with no resolving event:
   - it is censored ("awaiting resolution") only if t ≥ t_end − max(observed NACK→rtx delay, 1 TTI), else **A2-1 FAIL**;
   - its lines count in A2-6 as censored;
   - A2-8 is **NOT EVALUATED** for the affected UE: per-UE counts are inexact. **A2-V1 requires A2-8 PASS, so this stays fail-closed for the experiment.**
6. **The probe (A2-0)** applies steps 1–5 with the same helper. Whether it also gets A-2's "awaiting retransmission" censoring for BUF at the end (closing R-1) is **decision F1-b**: a separate, declared change.

**Unchanged guarantees.** A log without RTX / DISC lines never enters steps 1, 3 and 4. So **ACK-only behaviour is identical by construction**, and §8 tests it byte for byte on the preserved N = 1 / N = 2 runs.

**Fail-closed conditions** (all **A2-1 / A2-2 FAIL**, never a guess):
- a bound handle outside the candidates;
- a handle change within a unit;
- a count mismatch;
- too many rtx-proven or emptied units;
- an extract of a foreign MAC id on a PEND key;
- an unresolved discard;
- a pending group before the end window.
