### 2.1 Proposed parameter (decision A2-D1, not decided here)

**`perDl = 0.3` on every UE, `harqReduction = 1`.** A2-V1 used 0.1 on `ue[1]` only, and recorded 0 discards and no multi-NACK group (S1 closure §5).

**Sizing rationale. These are probabilities of the declared mechanism, not predictions of counts:**
- With independent attempts, a transport block is discarded with probability `perDl^(maxHarqRtx + 1) = perDl^4`. At 0.1 that is 1e-4; at 0.3 it is 8.1e-3.
- Two UEs both NACK a same-TTI pair with probability `perDl^2`. That is 0.01 at 0.1 and 0.09 at 0.3, and it is 0 when one UE is loss-free, as in A2-V1.

**Whether the minima are met is decided only by the run (§4).** A run that misses one is **not a valid diagnostic**: it is never extrapolated. A changed parameter is a new declaration and a new decision.

## 3. Non-perturbation twin (`check/m2s72_a2d.py twin`)

**Pair:** baseline `_A2DREF` (scheduler logging off) and diagnostic `_A2D` (on).
- Same seed, traffic, channel parameters and NACK injection (RNG 4), topology and scheduler configuration (R-1).
- The same command flags as the accepted Stage 5 runner (non-express, `--fingerprint=0000-0000/tplx`).
- The same binaries.

| Row | Must be identical | Method |
|---|---|---|
| **T-1** | Every non-console output: PCAPs and per-frame logs byte for byte; `.sca` / `.vec` without the run header (config name normalised); the eventlog's event and message records (log text excluded); the run fingerprint | The **accepted** E0 comparator `check_m2s72_e0.nonpert`, unchanged |
| **T-2** | The console log | Equal line by line after removing **only**: the diagnostic's `mac.schedulerDl` lines (the permitted diagnostic difference) and the declared volatile Cmdenv lines (`Assigned runID=`, `Elapsed:`, `Speed:`, `Messages:`, `** Event #`: wall clock and run id). The configuration name is normalised. **Every other line**, including every MAC, RLC and UE MAC log line, must be equal, in order. |
| **T-3** | — | The diagnostic has scheduler lines (`rtxAcid` among them); the twin has none |

**Permitted differences:**
- the scheduler log lines;
- wall-clock and run-id lines;
- execution time;
- the `.sca` / `.vec` run header (which records the configuration entries, including the log level).

None of these is a network behaviour. **Any other difference is NOT SHOWN (exit 1), fail closed.** The volatile list is declared from the OMNeT++ 6.5.0 Cmdenv forms. An undeclared difference on the first real twin fails, and is reviewed, never silently added.

**Canaries (run with every twin evaluation):**

| Canary | Expected |
|---|---|
| NC-T1 | One PCAP byte of the twin flipped (copy): T-1 must detect it |
| NC-T2 | One non-scheduler line added (copy): T-2 must detect it |
| NC-T3 | One extra scheduler line (copy): T-2 must **not** change (a permitted difference) |
| NC-T4 | Scheduler lines stripped (copy): T-3 would fail |

**Non-perturbation is never claimed from configuration loading or compilation.** It is shown only by T-1 … T-3 on the two real runs.

## 4. Coverage minima and the diagnostic verdict (`check/m2s72_a2d.py coverage`)

**Input:** the accepted A-2.1 record of the diagnostic:

```bash
check_m2s72_a21.py a21 <runs> M2S72-E0vN-q0-one0-n2-f1_A2D <records> --contract full
```

| Check | Rule (DR-07a) |
|---|---|
| C-0 | The record is of `…_A2D` |
| C-1 | Contract `full` |
| M-1 | NACK chains on more than one UE (per-UE `nack` > 0 for ≥ 2 UEs) |
| M-2 | Multi-NACK groups ≥ 1 (the A-2.1 coverage item) |
| M-3 | Discards after maxHarqRtx ≥ 1 (the A-2.1 coverage item) |
| M-4 | A2-4c **exercised**: PASS or FAIL. NOT EVALUATED or NOT EXERCISED is not a diagnostic. |

| Exit | Meaning |
|---|---|
| 0 | A valid diagnostic |
| 5 | **NOT A VALID DIAGNOSTIC** |
| 2 | Evaluation error (e.g. schema drift) |

**The A-2.1 verdict is reported verbatim and decided only by A-2.1:** VALID, NOT VALID or INCOMPLETE. In particular, an A2-4c FAIL is a valid diagnostic with a NOT VALID A-2.1 verdict.

**DR-07d: held for review.** A genuine multi-NACK group, a genuine discard, genuine structural censoring and a genuine A2-4c result are reported as **first genuine occurrence: held for review**.

**Separation.** The diagnostic counters go to `a2d-coverage-<cfg>.json`. They are never E0v-N performance measurements and never enter an E0v-N digest.

## 6. Procedure for the independent executor (V-6; after authorisation only)

1. Environment D-2:
   - OMNeT++ 6.5.0 / INET 4.7.0 / unmodified Simu5G 1.8.1 (`7477d266`), release builds;
   - `src/nasctime/m2/build.sh` at the authorised commit;
   - a fresh results root; the same binaries for both runs.
2. Resolution (no simulation):

   ```bash
   python3 -B check/m2s72_a2d.py resolve <records>/resolution -- <opp_run prefix>
   ```

   It must report AS DECLARED, and the outputs must equal the committed `results/M2-S7.2a-a2d/runconfig-*.txt` on their effective entries.
3. The commands of:

   ```bash
   python3 -B check/m2s72_a2d.py plan <nascTime> <simu5g> <inet> <root>
   ```

   in this order:
   1. the diagnostic, then the twin, each with its manifest;
   2. `twin`;
   3. `check_m2s72_a21.py a21 … --contract full`;
   4. `coverage`;
   5. manifest re-verification.

**Stop and keep everything:**
- on any non-zero simulation exit;
- on an evaluation error;
- on twin NOT SHOWN;
- on NOT A VALID DIAGNOSTIC.

Never rerun into the same root. Nothing is deleted.

**Acceptance (V-6):** the maintainer reviews the twin record, the coverage record and the A-2.1 record. Only then may the full-contract status of a configuration be decided. A2-V1's historical verdict is not reopened by V-6.
