### 2.1 How the S5-2 PU / AV / Q8 rows read at N = 1

`adapter-validate` runs after the smoke run, read-only, on that run's raw outputs, with UE 0 declared loaded in DL and UL (protocol §1: "load on UE 0, UL 1 × L_tot"). Its rows are defined in addendum §3.4. At N = 1:

| Row | What a PASS shows at N = 1 | What it cannot show at N = 1 |
|---|---|---|
| PU-1 | the run's one UE has a record with its NR MAC node id | distinct ids across UEs |
| PU-2 | per-UE Q8: every cohort Sync has exactly one fate, 0 UNEXPLAINED. The adapter's Q8 is exactly the E0 rule at N = 1: the strict `exclusion` attribution applies only when `n > 1` (contract test) | — |
| PU-3 | load-DRB accounting of UE 0 on 1.8.1 output | — |
| PU-4 | the adapter's log-order H-ARQ parser accounts for every TX feedback line: 0 orphan, 0 re-insert. Every attribution is A-1a | **A-1b and ambiguity resolution** (they need two UEs with the same process open). That part of rule A-1 stays untested on real output until E0v-N |
| PU-5 | every DL grant and H-ARQ insert belongs to UE 0's node | conservation across several UEs |
| AV-1 | Q8 internal consistency for UE 0 | — |
| AV-2 | the declared load (DL and UL on UE 0) is observed | — |
| AV-3 | **first real check of the per-UE UL source**: `ue[0]…nrRlc-um-1-1.tx` → `gnb1…rlc-um-<node>-1.rx` vectors exist. NOT EVALUATED is a finding (addendum §3.4) | — |

**What adapter-validate can and cannot settle.** A PASS of all eight rows is evidence toward decision S5-2-D2 (adapter acceptance); it does not settle D2. Part B is only partly exercised at N = 1, and part A on CP2 N > 1 output is still open, because the CP2 raw outputs were not kept for it. `check_m2s72_s5n.py run` stays refused for E0v-N.

## 6. Acceptance and rejection (committed definitions only)

The smoke run is **not an E0v result**: no P-E0v prediction is evaluated on it (protocol §9). Its outcome is judged by protocol §9 and the rows it runs.

| Result | Definition | Meaning |
|---|---|---|
| **Clean** | runner exit **0**: run outcome OK; per-run check PASS (every gate row of protocol §4, including F0-1 for this declared loss-free config); quick proxy completed; `controls-q8` as declared (§6); manifest re-verified (protocol §9) | the lifecycle and the N = 1 checks work on real 1.8.1 output; the MG-1 census can be frozen at review |
| Adapter validated at N = 1 | `adapter-validate` rc **0**: every PU / AV row PASS (PU-3 NOT APPLICABLE only for an unloaded UE, none here) (addendum §3.4) | evidence toward D2 within the §2.1 limits |
| Free-space stop | exit **3** | nothing ran |
| Non-OK outcome | exit **5**: SIM-ABORT / TIMEOUT / ERROR (protocol §4 classification) | not a result; raw outputs kept, tier B |
| Not clean | exit **6**: any of check, quick, controls, manifest not clean; every step still done and recorded | review finding. An MG-1 FAIL from an UNCLASSIFIED line is the expected kind of first-census finding (protocol §4: "frozen from the first reviewed run, not assumed") |
| Adapter not validated | rc **1** (a row FAIL or NOT EVALUATED), rc **2** (evaluation error) | adapter finding; does not change the smoke verdict |
