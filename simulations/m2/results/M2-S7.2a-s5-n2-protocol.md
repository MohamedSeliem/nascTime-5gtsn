## 3. Gap analysis: what the Simu5G 1.8.1 sources imply for N = 2

Findings from the unmodified sources (`7477d26`):

| # | Fact (source) | Consequence for the E0v-N checks |
|---|---|---|
| F-1 | One H-ARQ TX buffer **per UE** (`LteMacBase.h:36`, `HarqTxBuffers = map<MacNodeId, LteHarqBufferTx*>`). Each new PDU takes the **lowest free process** (`LteHarqBufferTx.cc:137`) | At N ≥ 2, two UEs holding the same process id at the same time is the **normal case**, not an exception |
| F-2 | The gNB feedback line (`:220`) names no UE. The feedback delay is fixed by the slot timing | Two UEs scheduled in the **same TTI** on the same process give identical gNB feedback lines at the same time, with identical age d*. A-1 cannot separate them and classifies both AMBIGUOUS. **This is correct and fail-closed, but PU-4 then FAILs and per-UE occupancy is NOT EVALUATED.** The candidates A-1 leaves open then surface as later re-inserts. In `one0-n2-f1`, UE 0 transmits in almost every TTI and UE 1 receives two 100 B base flows every 20 ms plus gPTP, so such coincidences are expected (P-N2-4) |
| F-3 | Overlaps across **different** TTIs have different ages | A-1b separates them by d*: **reachable and naturally exercised** at N = 2 (P-N2-3); no new scenario is needed to cover A-1b |
| F-4 | A NACKed unit is **kept** and retransmitted without a new insert line (`LteHarqUnitTx.cc:137-148`; `LteHarqBufferTx.cc:109`, `:242`) | A-1 closes the process on any feedback, NACK included, so a retransmission's feedback becomes ORPHAN (or is misattributed). Limitation **L-A1-NACK**: latent at N = 1, where 0 orphans means no DL NACK occurred at 50 m. Not fixed here: changing A-1 changes the validated rule. XA-4 detects it and classifies it |
| F-5 | PU-5 sums per-node grants and inserts that come from the same per-node partition | PU-5 cannot see a **consistent** cross-UE misattribution: control NC-n2-swap demonstrates this. PU-5 is unchanged (accepted definition). XA-1 / XA-3 / XA-5 cover the gap in this smoke |
| F-6 | The UE logs `H-ARQ RX: new PDU (id X ) inserted into process p` and `H-ARQ RX: feedback sent to TX process p Codeword  c … result: R` (`LteHarqBufferRx.cc:63`, `:78`). The MAC PDU id is preserved across the air (`LteMacPdu.msg:134`, `:143`). An air frame lasts one slot and is delivered at its end (`PhyBase.cc:120`, `:214`) | **Exact per-UE truth** for every DL insert and feedback, **already in every E0v / E0v-N log** (`M2S72S5-MACLOG-UE`). No configuration change is needed. This is the basis of XA |
| F-7 | No E0v-N runner mode. `s5n run` is refused until D2. `controls-q8` covers N = 1 / UE 0 only | Mode `smoke-n2`; labelled diagnostic use of `s5n run`; `controls-n2` |
| F-8 | As configured, every UE NIC module, the gNB and the direct callers share physical RNG 0 (RA-3, RA-4 COUPLED) | Realisations of UE 0 and UE 1 are coupled; immaterial to instrumentation correctness (§5) |

**Is the S5-2 architecture sufficient?**
- **For identities, accounting, gPTP fates and conservation by sums: yes.**
- **For attribution: it is correct but not verifiable from its own outputs.** PU-4 shows completeness, and PU-5 shows sums only. Nothing in S5-2 can show that an attributed line went to the *right* UE. Under F-2, PU-4 is also expected to FAIL.

The minimal necessary additions are:
1. an independent reference for attribution, read-only, from evidence the run already records;
2. multi-UE controls;
3. a runner mode.

A-1, PU-4 and PU-5 stay unchanged.

### 5.3 Mapping independence is not draw-sequence independence

| Property | What shows it | Status |
|---|---|---|
| **Mapping independence**: no physical RNG is mapped to modules of two UEs | static resolution (RA-3) | as configured: **not independent**; with the mixin: independent, except the 4 MULTI-UE modules |
| **Exclusive consumption**: every draw from stream 16 is made by a UE-0 module | static map **plus** the absence of other callers of that physical RNG; OMNeT++ does not log per-module draws | not shown by anything static. Changing `num-rngs` alone shows nothing, because a module with no mapping entry still draws from local 0 → physical 0 |
| **Draw-sequence independence**: UE 0's k-th draw gets the same number whatever UE 1 does | exclusive consumption, **and** UE 0's draw count unaffected by UE 1. The second does not hold under contention: the gNB channel model (one module, every UE's UL) and the scheduler tie-break make the draw order depend on N by construction (R-5) | **not achievable by mapping alone**; only the realisation of each UE's own NIC streams can be pinned |
| **Effect independence**: UE 0's outcomes unchanged when only UE 1's stream changes | paired runs | runtime only |

**Runtime evidence needed (separate approval; not part of this increment):**
- **E-R1:** with the mixin, `TtSyncMonitorRngProbe` (`rngDrawn:<j>` scalars) shows draws on 16 and 17. It also shows that RNG 0 is drawn only by the direct callers: their count is invariant to the UE NICs' activity. If 16 / 17 draw nothing, the per-UE NIC streams are inert at 50 / 58 m and isolation is moot for this geometry. The UE-side NACK counts of XA give the first indication.
- **E-R2:** paired runs, mixin, seed of RNG 17 only varied. UE 1's realisation changes (`rngDrawn:17` sequence effect, its UE-side NACK / reception pattern). For UE 0, its per-UE NIC outcomes (XA truth: receptions, NACKs) must be identical. Otherwise the difference is attributed to the MULTI-UE path, by tracing the first diverging TTI to a gNB-side draw.
- **E-R3:** the same with the seed of RNG 16 varied (symmetric).
- **E-R4:** the baseline mapping, with seed-0 varied, as the positive control: everything may change.

**Cost:**
- new mixin configurations (generator, regen / T0);
- the RngProbe typename override as in the M2S71-R configs;
- 4–6 short N = 2 runs.

It belongs with Block F / design stage 7 (addendum §2.5).
