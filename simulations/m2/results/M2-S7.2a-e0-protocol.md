# M2-S7.2a Stage 5: revised experimental protocol, checker specification, predictions and E0 configuration (declared before any E0 run)

Declared 2026-11-03, before any E0 run. Authorisation: review of 2026-11-03 11:35 ("CONDITIONAL APPROVAL… Stage 5 implementation preparation and E0 calibration only, with a mandatory STOP after E0").

**Scope.** E0 only. E3, E1, E2 and E4 are not run; they need separate authorisation. No Stage 6, no new C++, no upstream change, no GitHub push. Earlier oracles are unchanged and all earlier records are kept.

**Output directory.** `results/M2-S7.2a-e0`. It does not exist before the batch, and `m2s72.sh e0` refuses to start if it does.

**Run from.** A clean tree at the commit that adds this file. That commit is recorded in `env-*.txt`.

**Research objective.** The aim is explainable dependability analysis across timing, reliability and resilience. E0 is not a scalability test. It establishes, from evidence, where the single-UE cell stops keeping up. Only after that may any later experiment call a load regime "overload".

## 1. Definitions (review item 1)

Every quantity below is measured separately, and none is inferred from another.

| Term | Definition in E0 | Evidence |
|---|---|---|
| **Offered traffic load** | What the sources produce. DL is 1400 B (PCP 0, VLAN 42) every 0.25 ms / F from 0.3005 s. UL is 1400 B every 0.25 ms from 0.1005 s. The rate is checked exactly per run (row CFG-rate). It is also reported where the load enters the gNB RLC, as RLC SDU bytes (1420 B per frame). | listener and talker[0] egress logs; gNB RLC TX `receivedPacketFromUpperLayer` |
| **Achieved throughput / service capacity** | Load bytes delivered by the UE RLC per second over [2 s, T_end), and the MAC DL grant bytes per second. Service capacity is the plateau of achieved DL throughput as offered load grows. It is a property of this cell and this configuration: N = 1, 50 RB, CQI 15, 1 ms TTI, MaxCI (Q-0) or QoS-aware (Q-d) scheduler. | UE RLC RX `sentPacketToUpperLayer`; MAC log grants |
| **HARQ process exhaustion** | A MAC PDU deleted because no HARQ TX process is free (`LteMacEnb.cc:585`). Also reported: the largest number of simultaneously busy processes, from insert to ACK/NACK. | MAC log, per MAC PDU |
| **Sustained queue growth** | Of a DRB, from the replayed RLC TX backlog (bytes queued, not yet completed). True iff the per-second minimum of the backlog strictly increases in each of the eight windows [4 s, 5 s) … [11 s, 12 s). Reported per DRB: the gPTP DRB, and the load DRB 1. | RLC replay (vectors) |
| **Deadline violation** | Sync residence (NW-TT rx → DS-TT tx) > 5.5 ms, and Follow_Up lag > one Sync interval (125 ms). Undelivered counts as +∞. These are exploratory thresholds (§5). | PCAP |
| **Confirmed packet loss** | A frame whose own RLC PDU was destroyed **and** whose discard was observed in the MAC log at that TTI (HARQ-process deletion, NACK, MAC buffer overflow). | Q8 (§2) |
| **Right-censoring at the horizon** | A frame with packet-specific evidence that it was still inside the system at T_end (§2). | Q8 (§2) |

**"Overload" is a label assigned only from evidence, never from a factor.** A run is called overloaded iff its load DRB shows sustained queue growth **and** its achieved DL throughput is below the offered DL throughput. E0 is N = 1 only. Its measured capacity is **not** taken as the capacity threshold for N = 2, 4 or 8, because the scheduler, HARQ and RB sharing differ there. The labels 2×, 4× and 8× are load factors, not overload claims.

## 2. Q8 per-packet accounting (review item 2)

Every GM Sync and Follow_Up (domain 0) gets exactly one fate. Each fate states its **last confirmed location** and its evidence.

**Chain.** Each link is a recorded observation of that very frame:

GM tx → NW-TT rx → NW-TT tx → UPF N6 rx → UPF N3 tx (GTP-U DL, gPTP seq) → gNB RLC UM TX SDU → RLC replay → UE RLC delivery → UE tx → DS-TT rx → DS-TT tx → slave rx

Links that are inferred rather than observed, and the checks on them:
- **gNB RLC UM TX SDU.** The k-th SDU of the Sync (resp. Follow_Up) size on the gPTP DRB is mapped to the k-th N3 copy. This holds because the DRB is FIFO and the sizes are unique (Sync < Follow_Up < 110 B < data). The mapping is checked: no SDU arrives before its N3 copy, and there are never more SDUs than N3 copies.
- **RLC replay.** The NR UM single-segment-per-PDU model (S7.1, validated in P1) is validated per run. Every observed UE RLC delivery must be predicted, and every predicted delivery due by T_end must be observed or explained. This applies to every SDU on the DRB, load included. If the model fails, Q8 fails.

**Fates.**

| Fate | Requires (packet-specific) |
|---|---|
| delivered | received by slave 0 by T_end |
| **censored** | One of the following, each specific to this frame:<ul><li>its own SDU is in the replayed RLC TX queue at T_end (not started, or partially sent, with the bytes stated);</li><li>its own last RLC PDU was sent with the delivery due after T_end;</li><li>its own DS-TT hold is open at T_end;</li><li>its own last observation plus the largest latency of that stage in this run is > T_end (still on a link or inside a node).</li></ul> |
| **lost** | its own PDU was destroyed **and** a discard was observed in the MAC log at that TTI |
| invalid / late | its own DS-TT discard event (the S7.1 event classes) |
| **UNEXPLAINED** | Anything else. This includes a destroyed PDU without an observed discard, and a frame missing after a stage although its latency bound had passed. **Q8 fails.** |

**Rules.**
- Aggregate queue occupancy is never used to classify a frame. The backlog series is a reported metric only.
- Unexplained loss is never reclassified as censoring.
- **Pairs** (one GM Sync with its Follow_Up) are classified, in this order: UNEXPLAINED (if either frame is), used / ignored (INET's slave rule), lost, invalid, late, censored.
- Conservative reliability metrics rank every non-used pair as +∞. The classes stay separate in every table.

**Q8-x (MAC-log consistency, gated).** The MAC log must match the same run's vectors:
- RLC TX SDUs and PDUs: log vs vectors;
- UE RLC deliveries: log vs vectors;
- MAC overflow lines vs the `macBufferOverFlowDl` scalar;
- no MAC PDU deletion at the TTI of a delivered gPTP frame;
- grants and scheduler loops present;
- no UNCLASSIFIED loss-like log line (fail closed).

## 4. Configurations, generator and MAC log (review items 6, 7, 9)

**Generator (Python only, `tools/m2s72_gen.py`).** It adds load-capable variants `M2S71-<opt>-Ca-sus@L`, whose base carries **no** load, and load mixins `M2S72LD-<short>-<placement>-n<N>-f<F>[-u<U>]`.

**Placements:**
- **one0:** L_tot on UE 0;
- **sym:** L_tot divided equally over N UEs, with per-UE interval 0.25 ms · N / F.

**Fail-closed checks:**
- the effective app[3] settings of the source must be the S7.1 L_tot values (`LOAD_REQ`);
- intervals must be an exact number of ns;
- placement `sym` is refused at N = 1;
- N must be generated and ≤ 8;
- no base-flow setting may reach a load app.

**Tests.** `check/test_m2s72_gen.py` has 49 cases: 28 earlier and 21 new, all PASS.

**Exact verification.** `m2s72_gen.py verify` resolves every E0 config and each twin with OMNeT++ (`opp_run -q runconfig`). It checks every load value as the first match of its parameter path, rejects any foreign app setting, and checks HARQ16, the listener MAC, numUe and the MAC-log entries. Each twin must equal its E0 config minus exactly the MAC-log entries. The same check covers 74 test configs of the one0 / sym mixins (N = 1–8, F = 0.5–8, U = 0.5 and 2), which are **not** runnable configs of `m2s72.ini`.

**E0 configs (`m2s72.ini`):**
- `M2S72-E0-<q0|qdu>-f<1|2|4|8>` extends M2S72-MACLOG, M2S72LD-<opt>-Ca-L-one0-n1-f<F>, M2S72-HARQ16, M2S72-SL, M2S72-L, M2S72-ev, M2S72D4N1-<opt>-Ca-L, M2S72N1-<opt>-Ca-L, M2S72B-<opt>-Ca-L.
- Settings: N = 1, C-a clocks, D-4 timing, 12 s. DL load factor F on UE 0; UL stays 1 × L_tot.
- HARQ16 is an **experimental control, not a deployment recommendation**. HARQ-5 deletion is a Simu5G-specific behaviour of the tested configuration.

**MAC-log twins.** `M2S72-E0NL-q0-f<F>` is the same config without M2S72-MACLOG. The runner runs the twin of the highest Q-0 factor executed.

**MAC log (M2S72-MACLOG, observation only):**
- logs at level `info` the gNB MAC, the gNB RLC UM TX entities and the UE RLC UM RX entities;
- prefix `%t|%M|` (simulation time | context module path); stdout is gzip-compressed;
- parser: `check/m2s72_maclog.py`.

The parser keeps separate identities for:
- scheduler grants (DL / UL, per connection);
- MAC PDUs;
- HARQ TX insertions;
- HARQ feedback (ACK / NACK);
- HARQ-process deletions;
- MAC buffer overflows;
- MAC buffer occupancy;
- RLC TX SDUs, PDUs and drops;
- RLC RX deliveries and discards;
- UNCLASSIFIED loss-like lines.

**Non-perturbation (gated row NONPERT).** E0-q0-f<top> is compared with E0NL-q0-f<top>:

| Output | Comparison |
|---|---|
| PCAPs and per-frame logs | byte-identical |
| .vec / .sca | identical without the run header (config name normalised) |
| .elog | event, message and module records identical, and the UPF MAC-table log lines identical (prefix removed). The MAC-log lines and the index / snapshot records, whose byte offsets move with file size, are excluded |
| .vci | excluded (the .vec byte-offset index) |
| fingerprint | equal |

## 5. Exploratory onset thresholds (review item 4)

The thresholds are:
- first confirmed lost or right-censored cohort pair;
- Sync-residence p99 > 5.5 ms;
- max |e| > 1 µs (the M2-S6 steady-state between-step maximum, from the exact oracle);
- P(used) < 0.99.

These are **exploratory reporting thresholds** for ordering onset. They are not industrial application requirements.

**Sensitivity is reported** at:
- residence p99 > 2.75 / 5.5 / 11 ms;
- max |e| > 0.5 / 1 / 2 µs;
- P(used) < 0.95 / 0.99 / 0.999.

## 7. Matrix, storage budget and stopping conditions (review item 10)

**Matrix.** E0 is `M2S72-E0-<q0|qdu>-f<1|2|4|8>`, seed 0 (8 runs), plus one MAC-log twin. The runs go one at a time (JOBS = 1, memory: unbounded NR RLC TX buffer), in the order F = 1, 2, 4, 8 and, within each factor, Q-0 then Q-d.

**Stop conditions** (preserve the partial record, report):

| Condition | Rule |
|---|---|
| Free space at batch start | < 20 GB |
| Free space before any run | < 10 GB |
| Run time | > 3 × estimate. Estimates: F = 1 4 min, F = 2 6 min, F = 4 10 min, F = 8 18 min. The proposal's "3–8 min" is revised upward before the batch, because the MAC log and 1 s trials showed ≈ 15 s per simulated second at F = 1 |
| Simulator | runtime error |
| Escalation | Declared rule: after each factor, the runner's proxy is the fraction of cohort Syncs not received by DS-TT 0 by T_end (an upper bound of the censored fraction). If it is > 50 % in **both** Q-0 and Q-d, higher factors are not run |
| After the check | any gated row FAILs or any control misses its prediction |

**Storage budget.** ≤ 16 GB raw for the batch (estimate ≈ 13 GB). The deletion audit is in `results/M2-S7.2a-e0-prep/deletion-audit.txt`: 24 GB free after the authorised cleanup.

**Committed after the batch:**
- check output and metrics CSV;
- `raw-outputs.sha256`, which covers PCAP, CSV and the MAC logs;
- `env-*.txt`, the regeneration record and `e0-runs.txt` (actual runtime and storage per run).

Raw runs stay local until the review.

## 8. Disclosed implementation trials (not E0 results)

These were made during implementation, before this file, in the session scratchpad, outside the record:

- **1 s mechanics runs** of `M2S72-E0-q0-f1`, `M2S72-E0-qdu-f1` and `M2S72-E0NL-q0-f1` (`--sim-time-limit=1s`), plus a 1 s MAC-log on/off pair (TR-log / TR-nolog). They established:
  - the log module paths;
  - non-perturbation of the 1 s pair (36 raw files identical, equal fingerprints a17f-3db9);
  - the checker plumbing;
  - the control mechanics.
- **What they observed:** at F = 1, Sync residence up to ≈ 4.16 ms (Q-0) and ≈ 4.09 ms (Q-d), Follow_Up L_max 6.05 ms (Q-0), max busy HARQ processes 6, and DL MAC PDUs up to 7250 B with all 50 RBs allocated.
- **These observations informed E0-P1, E0-P3 and E0-P7.** No run above F = 1 was made.
- **The controls were dry-run there.** Their mutations were fixed then (NC-q8-deliv / NC-q8-noevid now also remove the matching MAC-log delivery and later observations), and PC-q8-lost was added.
