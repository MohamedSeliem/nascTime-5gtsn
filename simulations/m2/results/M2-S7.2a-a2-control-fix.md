## 1. Verdict of the investigation

| Control | Where the problem lies | Mutation | Data propagation | A-2 rule |
|---|---|---|---|---|
| NC-A2-shift | **the mutation**: it changed no time stamp, so the checker received the original times | defective | correct (it passed exactly what was built) | **correct**: A2-3 FAILs on a genuinely retimed event (T-a23) |
| NC-A2-scalar | **the mutation**: it perturbed a line A2-8 does not read | defective | correct | **correct**: A2-8 FAILs on a perturbation of any compared value down to 1e-6 (T-a28) |

Both controls were **no-ops on real output**: the checker's input was not mutated in the way the control claimed. Neither A2-3 nor A2-8 had a defect. No expected result and no gate was changed.

## 2. NC-A2-shift: trace from construction to checker

**Construction** (`check_m2s72_a2.py` at `2a1032e`, line 259):

```python
ls = _put(ls, x["t"] + MS, [y.replace(_ts(x["t"]), _ts(x["t"] + MS), 1) for y in lines[s0:s1 + 1]], at_start=True)
```

with `_ts(t) = f"{t // S}.{t % S:012d}"`. It always writes 12 decimals: 1.013 s → `"1.013000000000"`.

**The real log prefix.** The runner logs with `cmdenv-log-prefix = "%t|%M|"`. In OMNeT++ 6.5.0, `%t` is `stream << simulation->getSimTime()` (`src/envir/logformatter.cc:191-192`), i.e. `operator<<` of `SimTime`, which prints the **shortest** decimal.

Demonstrated here by compiling against the 6.5.0 libraries (record §7):

| `SimTime::parse` | printed |
|---|---|
| `1.004` | `'1.004'` |
| `12` | `'12'` |
| `0.3005` | `'0.3005'` |
| `1.000000000001` | `'1.000000000001'` |

**Original vs mutated value** (reproduction with the real prefix format; record §6):

```
ORIGINAL   1.013|M2S72Bridge.gnb1.cellularNic.mac|LteHarqBufferTx::receiveHarqFeedback - start
           1.013|…|LteHarqUnitTx::pduFeedback - Welcome!
           1.013|…|	 pdu_ has been sent and received correctly
           1.013|…|H-ARQ TX: feedback received for process 0 codeword 0 result is ACK
search string _ts(t) = '1.013000000000'   found in prefix: False
lines changed by the replace: 0
```

**What the checker received:**
- the four lines, unchanged and still stamped `1.013`, moved in **list position** to the start of 1.014;
- `A2.replay` reads the time of each line from its own prefix, so the feedback age stayed t − last_tx = d* (5 ms);
- one age, therefore A2-3 PASS.

That is the right answer for the input it was given.

**Why the tests did not see it.** The source-faithful generator writes 12-decimal prefixes (`m2s72_harqfix.ts`), so on fixtures the text replace matched. `T-controls` passed; the real format was never tested.

**Correction (smallest):**
- `_retime(line, t)` sets the time field before the first `|` explicitly, written as OMNeT++ writes it (`_now`), whatever the original form.
- The control also checks that every moved line now parses to t + 1 TTI.
- It reports the evidence, e.g. `mutation: 4 lines retimed '1.013' -> '1.014' (feedback age 5 -> 6 ms)`.

## 3. NC-A2-scalar: trace from construction to checker

**Construction** (`2a1032e`, lines 333-336):
- it perturbs the **first** `.sca` line whose name is `harqErrorRateDl:mean`, adding 0.001;
- it never asks whose line that is.

**What A2-8 reads** (`m2s72_a2.scalar_row`):
- only the modules in `sca_nodes()`, i.e. UE **NR** MACs `M2S72Bridge.ue[k].cellularNic.nrMac` with a `macNodeId` parameter;
- in those, `harqErrorRateDl:mean` and `harqTxAttemptsDl:mean`.

**Why the first line is not one of them.** The statistic is declared in `LteMacBase.ned` (`@statistic[harqErrorRateDl] … record=mean,vector`, lines 56-79), so **every** MAC module records it:
- the gNB MAC (`gnb1.cellularNic.mac`);
- the UE's LTE-leg MAC (`ue[k].cellularNic.mac`);
- the UE NR MAC.

The DL samples are emitted only on the UE NR MAC (`LteHarqUnitTx.cc:165-195`). The other modules record `nan`, and they are written to the `.sca` before the UE NR MACs. `nan + 0.001 = nan`, so even the textual change was a no-op on a `nan` line.

**Original vs mutated value** (reproduction with that layout; record §6):

```
line perturbed by the 2a1032e control: scalar M2S72Bridge.gnb1.cellularNic.mac harqErrorRateDl:mean nan
module compared by A2-8: False
A2-8 on the mutated file: PASS (it read the same UE NR MAC values as before)
```

**On the preserved runs**, step B2 of §5 prints the actual line order of each `.sca`. It is read-only and confirms which module the old control touched.

**Why the tests did not see it.**
- `T-controls` gave no `.sca`, so the scalar control was NOT BUILDABLE there.
- `T-cli`'s synthetic `.sca` held only UE NR MAC lines. The first line happened to be a compared one, and the test checked only that the control was listed, not its status.

**Correction (smallest):**
- The control perturbs the `harqErrorRateDl:mean` line of a module A2-8 compares (in `sca_nodes()`, value not `nan`).
- It verifies that A2-8's own reader (`m2s72_a2probe.scalars`) returns the mutated value from the mutated file.
- It reports, e.g. `mutation: M2S72Bridge.ue[0].cellularNic.nrMac (node 2049) harqErrorRateDl:mean 0 -> 0.001, A2-8 reads 0.001`.
- With no compared line, it is NOT BUILDABLE, never a pass.

## 4. General correction: no negative control can pass as a no-op

`controls()` now records whether the checker's input differs from the unmodified input: the line list, the grants, and the `.sca` content.

A negative control (`NC-*`) whose input is identical is **NOT AS DECLARED** with `MUTATION NOT APPLIED`, regardless of the rows. Positive controls are unaffected.

**Other controls reviewed for the same defect class** (record §8):
- The remaining uses of the 12-decimal `_ts` only *write* new lines. Every reader parses them by value, so mixed prefix forms are harmless.
- The remaining text replaces change message text, not times: result, node id, PDU id, scheduler user, module.
- None depends on the prefix format, and all are now covered by the guard.
