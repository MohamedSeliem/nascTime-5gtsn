## 1. SG-403: strengthened interpretation rule for backlogged Q-d DL connections

**Evidence base** (Simu5G 1.8.0 source, read-only):
- `QoSAwareScheduler::prepareSchedule` logs `CID--->` for **every** connection in the carrier's active set, *before* any eligibility test (`QoSAwareScheduler.cc:127–128`).
- The following merely skip a connection while leaving it active, so it is still logged as a candidate:
  - CQI, band or codeword exclusions (`:141–147`);
  - H-ARQ ineligibility (`eligible = false`);
  - quota or capacity limits.
- A connection leaves the active set only through `active = false` from `requestGrant` / `scheduleGrant` (`:231–234`), or when its node no longer exists (`:132–135`).
- `scheduleGrant` returns `active = false` legitimately when the queue is empty (`LteSchedulerEnb.cc:283–287`), and erroneously at `:403–408` when a **capped** grant drives `toServe` to 0 while backlog remains.
- A new SDU re-notifies the MAC and re-activates the connection.

**Classification** of every backlogged DL TTI (`diag_m2s72_dl_active.py` revision 2, `classify()`), with backlog from the gNB RLC UM TX replay:

| Class | Meaning | Consequence |
|---|---|---|
| served | Candidate, granted > 0 B | — |
| **CAND-NOT-SERVED** | Candidate, no grant. **Legitimate scheduling ineligibility or non-selection** | Reported only |
| **CONFIRMED-403** | Not a candidate, and **all** of: (i) candidate in the previous TTI t′ with a **capped** grant (granted = limit > 0); (ii) every TTI from t′+1 to t backlogged and not a candidate; (iii) **no SDU of that DRB arrived in [grant time at t′, start of TTI t]**, inclusive, because an arrival exactly at either bound has an ambiguous order | The run is "Simu5G :403-affected" |
| **UNEXPLAINED** | Not a candidate, and not CONFIRMED-403. Includes: an arrival in the window; an ambiguous arrival time; no preceding capped grant; an uncapped (MaxCI) grant; backlog before the first activation | Fail closed |

The backlog at a CONFIRMED-403 TTI is therefore residual data that was already queued when the capped grant cleared the active flag.

**Scope.** The classification is applied to **every** E2 run: Q-0 and Q-d, every N, placement and factor. **No interarrival-interval assumption is used.** A mean interval ≤ 1 ms does not exempt a run. The revision-2 H-DL-403 statement ("can appear only … per-UE interval > 1 ms") is kept as a declared, falsifiable hypothesis, but it never excludes a run from the check.

**Rule (row SG-403, `check_m2s72_e2.py`; not an RB row).** CLEAR requires 0 CONFIRMED-403 **and** 0 UNEXPLAINED in the run.
- **CONFIRMED-403 > 0:** the run is excluded from every clean scheduler-comparison claim. This covers its own capacity and timing values as QoS-scheduler behaviour, and every Q-0 / Q-d comparison that uses it. The batch **stops for review**. The run's raw evidence is retained.
- **UNEXPLAINED > 0, or missing evidence:** the batch stops for review, and the run is not interpreted.

**Runner (`m2s72.sh e2rb`).** After each of the four runs it runs `diag_m2s72_dl_active.py --classify` on that run. Any non-CLEAR result ends the batch with `STOP FOR REVIEW` (exit 5) before the next run. No raw output is deleted. The ≥ 20 GB start rule is now checked before anything is built or created. A refused start therefore leaves no `results/M2-S7.2a-e2rb` that would block a later start.

## 2. Storage

- That check covers all gates, Q8, Q8-x, the timing oracles, the six controls and the MAC-log non-perturbation comparison. It reproduced the committed `e0-metrics.csv` byte for byte, and its verdict (PASS, controls 6 / 6).
- **Every raw file class is required by at least one check:** pcapng, eventlog, measurement / trafficConditioner CSV, MAC log, `.vec`, `.sca`. Only the `.vci` indexes (4 MB) are not.
- The revision-2 retention candidate D-S2 ("delete PCAP / CSV / eventlog after the check") is therefore **withdrawn**. It would make Q8, the timing oracles, F0-7d and the non-perturbation control unreproducible.

**Options for the decision.** Nothing has been applied.
- (a) Run `M2S72_E2_AUTH=… ./m2s72.sh e2rb` on a machine with ≥ 20 GB free plus ≈ 3.6 GB for the runs, e.g. the local VM after the bundle import. The runner refuses any Simu5G other than the accepted 1.8.0 library, by hash.
