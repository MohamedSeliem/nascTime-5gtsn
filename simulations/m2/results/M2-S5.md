# M2-S5: online downlink two-step gPTP correction across the 5G–TSN bridge (results)

**Verdict: PASS.**

The prerequisite gates R0, R1, G0 and V0 were recorded in that order, before the code they guard (§1).

All 71 rows of `M2-S5/check.txt` pass:
- G0 and V1: the gates rerun on the final code;
- A0 and E1;
- the correction rows C1–C8, S1–S7, P1–P2 and G1;
- 25 fault cases;
- the hold/timing rows H0–H5 and W1;
- 16 negative controls, each failing exactly its declared rows with an exact correctionField signature.

The M1, M2-S0, M2-S1, M2-S3 and M2-S4 regressions are byte-identical to their records (§7).

**What changed.**
- **NW-TT `eth[1]`:** the Sync's first-bit ingress time TSi is recorded. The Follow_Up's correctionField gets the NW-TT's measured upstream link delay (M2-S4 engine), and a simulation-only tag carries TSi with the Follow_Up (option B).
- **DS-TT `eth[1]`:** the Sync's first-bit egress time TSe is recorded. The Follow_Up gets cf2 = cf1 + (TSe − TSi), the tag is removed and the FCS recomputed.
- **Mechanism:** the real Follow_Up packets are rewritten at both translators, by a new port module `nasctime.m2.TtPtpPort` that contains the M2-S4 Pdelay engine unchanged. OMNeT++, INET and Simu5G are unchanged; no FRER, no legacy code, no drifting clocks.

**Main result** (M2S5 seeds 0–9, N3 fragmentation, saturating load, load + 16 HARQ):

| | M2-S4 (no correction) | M2-S5 |
|---|---|---|
| Slave clock error after step 1 (seed 0) | −5 000 626 ns | **0 ps** |
| Max \|error\| after step 1 (seed 0) | 6 002 226 ns | **0 ps** at every step and every 1 ms sample |
| Initial slave offset 1.234 567 891 ms (S4) | — | removed exactly at step 1, 0 ps afterwards |
| Online vs offline (S3) | — | cf2 = D_NWTT + Res predicted from the **M2-S4 records**, for every Sync; the recorded clock trace = the M2-S3 model's prediction, all 5 081 samples |

- In the normal runs the slave clock starts at GM time, so every step correction is 0 ps. That the correction is applied, not merely harmless, is shown by S4 (an offset is removed exactly), by M2-S4 (−5 ms without it) and by the negative controls (each mistake yields its exact error).

**Scope of claims.**
- **Claimed:** minimum viable timing correction across the 5GS for downlink two-step gPTP with ideal clocks, a single domain and static roles. Inside the simulation the INET slave clock error is 0 ps exactly, and it equals the M2-S3 oracle's prediction from the M2-S4 records.
- **Not claimed:**
  - IEEE 802.1AS (2020 + Cor 1, 2025), IEEE 1588 or 3GPP compliance (every 802.1AS/1588 pointer in the design remains [unverified]);
  - rate-ratio correctness (rr = nRR = 1);
  - holdover with drifting clocks;
  - wire-faithful Suffix carriage;
  - timing neutrality of the hold beyond one unlimited FIFO.

## 5. Findings

- **INET slave crash (F8) reproduced.** In FD6 (FU 3 after Sync 4), before the fix the DS-TT forwarded FU 3 behind the already-queued Sync 4. The INET slave paired it with Sync 4, reset its state, and crashed with a null dereference in `Gptp::processFollowUp` on FU 4 (segfault, backtrace in the run log). The fix (`645de0e`) discards a Follow_Up when any newer Sync is queued.
- **INET slave initial pdelay = −1 s** (`Gptp.h:184`, `clocktime_t pdelay = -1`). A Follow_Up processed before the first Pdelay exchange steps the clock by about −1 s, followed by a −5052 ppm compensation (seen in an exploratory unit run). The M2-S3 model represents the sentinel as −1 ps, a latent mismatch that no recorded run exercises: in the 5GS the first exchange is at t ≈ 0, and the unit configs now start Pdelay before the first Sync.
- **M2-S4 erratum (row E1).** The M2-S4 checker looked for GTP-U on UDP port 2152, but Simu5G 1.8.0 uses port 31, so its N3 sub-check of T1 found no frame (vacuous). Re-checked here on the M2-S4 runs: 57 076 GTP-U inner frames, 1 014 Sync/Follow_Up, **0 Pdelay**. M2-S4's conclusion holds; its N3 evidence was missing.
- **The INET GM** sends a Follow_Up per transmitted Sync copy, none for a dropped or foreign-domain Sync, and cannot transmit gPTP frames that are not complete `FieldsChunk`s.

## 6. Limitations

- **Clocks:** ideal clocks only; rate-ratio handling is computed and carried but not validated (N9 shows only detection). The INET slave ignores the TLV rateRatio.
- **Holdover:** S6 shows 0 ps between steps only because both clocks are ideal. Holdover with drifting clocks is not modelled or claimed.
- **Carriage:** TSi is a simulation-only region tag; no Suffix bytes are carried (sizes differ from a real two-step bridge). A class I Follow_Up still crosses the 5GS. Tag survival is demonstrated (V0/V1) for well-formed Follow_Ups; class M Follow_Ups are discarded at the NW-TT, so their runs lose one frame in the 5GS (listed).
- **TSi association:** TSi is taken by tree id at the NW-TT slot, which requires the Sync to reach the slot in the event of its own reception end. A delay or reorder between the PHY and `syncIn` is not supported.
- **Wire precision:** INET serializes cf in whole ns; sub-ns values are exact only inside the simulation (W1).
- **Hold:** timing-neutral for the single unlimited FIFO only. A Sync lost below the hold point releases a late burst (H4: 9.91 ms). The 5GS runs never hold.
- **Baseline:** G1 accepts the F11 differences (slave-clock-driven Pdelay and the UL frames queued behind it) and lists each one.
- **Scope:** DL only; one UE; domain 0; static roles; no Announce/BMCA, no receipt timeouts, no residence-time bound. Other domains pass uncorrected (not ours to correct).
- **Fault policy:** nascTime's, pending the 802.1AS-2020 + Cor 1 state machines [unverified].
