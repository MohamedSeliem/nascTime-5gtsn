# M2-S0: chunk-level timestamp tag across the Ethernet – 5G – Ethernet bridge (results)

**Verdict: PASS.** All 21 rows of `M2-S0/check.txt` pass: structure S1–S2, acceptance A1–A10 and negative controls N1–N4. The M1 regressions are unchanged (see the Regressions section).

**Main finding:**
- On unmodified OMNeT++ 6.4.0 / INET 4.7.0 / Simu5G 1.8.0, a chunk-level tag set by a translator on the Ethernet payload of a frame arrives at the opposite translator with the exact values set at ingress. This holds in both directions for every frame delivered.
- The values are a picosecond-exact ingress time, the translator id and a frame id. They survive:
  - GTP-U encapsulation;
  - SDAP/PDCP/RLC/MAC, including RLC SDUs cut and reassembled;
  - N3 IPv4 fragmentation;
  - saturating load with MAC losses.
- With the tag layers in place, the Ethernet wire format and every recorded statistic stay bit-identical.

This validates the **carriage mechanism** only. Nothing is written into any frame, and there is **no gPTP / transparent-clock / residence-time correction**.

## What was built

- **`TtTimestampTag`**: an INET `TagBase` with `ingressTime` (simtime), `ingressTtId` and `frameId`.
- **`TtTimestampLayer`**:
  - It fits the default-empty measurement-layer slot of INET's `LayeredEthernetInterface`, set from ini only.
  - It is placed on each translator's TSN-side port `eth[1]`, where it runs in translator mode: nwTt has id 1, dsTt id 2.
  - It is also placed on both stations' `eth[0]` in audit mode.
- **Its two processors:**
  - **RX path (ingress):** checks the frame structure, then replaces the whole payload region with tagged copies of its leaf chunks. Shared chunks are never mutated. It then verifies that the frame bytes are unchanged and that the tag covers exactly the payload.
  - **TX path (egress):** collects the tag regions on the payload leaves. It requires full coverage and a single value, logs the values, then strips the tag. It verifies that no tag remains at any chunk level and that the bytes are unchanged.
- **Logging:** per-frame CSV logs with exact simulation times and an FNV-1a hash of the payload bytes. The checker joins these logs to PCAP by payload identity, recomputing the hash from the captured bytes.

## Packet structure at the insertion point, confirmed before tagging (S1, S2)

`M2S0-probe`, `-probe-frag` and `-probe-load` run the layer in probe mode, which records the chunk structure and changes nothing. They cover all four slots, RX and TX, at base, N3-fragmentation and load settings: 94 530 frames in 8 structures (`M2-S0/census.txt`).

- Every frame is `[EthernetMacHeader][Ieee8021qTagEpdHeader iff 0x8100][payload chunk(s)][EthernetFcs]`:
  - On RX, the data part starts after the 8 B PHY header (front offset 8 B).
  - The FCS chunk is present on RX and TX.
  - No `EthernetPadding` occurred, since every frame is ≥ 64 B.
- The payload is one chunk, except the gPTP Sync. INET's Sync is `GptpSync` (44 B) + a 2 B `ByteCountChunk`, and both are tagged as payload.
- The payload leaf types are the same at the far translator after crossing the 5G system, also with N3 fragmentation, where INET's reassembly returns the original chunk.
- Any other structure stops the run with a named error. The synthetic-frame self-test (10 cases, 40/40 runs) covers:
  - 802.3 length/LLC;
  - 0x8100 without a Q-tag chunk;
  - stacked C-tags;
  - S-tag;
  - no MAC header;
  - headers only;
  - MAC header inside the payload.
- Packet streaming through the slot also fails explicitly.

## Timestamp and recovery events (exact definitions)

- **Ingress event (`ingressTime`):** on the translator's TSN-side port `eth[1]`, RX path, measurement-layer slot. It runs in the same simulation event in which that port's MAC layer emits `packetReceivedFromLower`, the PCAP inbound record. That event is the end of reception of the frame's last bit.
- **Recovery event:** on the opposite translator's `eth[1]`, TX path, measurement-layer slot, above the MAC queue. It runs in the same event as the frame's reception on that translator's 5G-side port `eth[0]`.
- **What residence covers here:** the time from TSN-port reception at TT_in to 5G-side-port reception at TT_out. It does not include queueing or transmission on TT_out's TSN port.

Verified with **no tolerance**, from pcapng at 1 ps resolution (A2, A2b, A4):
- `ingressTime` = PCAP inbound time at TT_in `eth[1]`, for every tagged and every recovered frame: 0 ps deviation.
- PCAP inbound at TT_in `eth[1]` − PCAP outbound at the sending station = 50 ns, for all 10 740 frames. This is propagation only, over 10 m of cable at 2e8 m/s; INET records outbound frames at the end of transmission.
- Recovery time = PCAP inbound time at TT_out `eth[0]`; recovered residence = PCAP(TT_out `eth[0]` in) − PCAP(TT_in `eth[1]` in), exactly.

**Accounting for frames not delivered (A1, A6, A7).** Every frame tagged at ingress but not delivered to TT_out by the end of the run is placed by an RLC replay of the TX entity of its DRB (the O-tail method):
- not yet at the TX RLC;
- still in the TX RLC at the end;
- left the TX RLC in the last 10 ms (in flight);
- left the TX RLC earlier and never delivered.

The replay maps SDUs to frames by order on the DRB, and that mapping is accepted only if SDU size − frame size is one constant. Only the load run with 5 HARQ processes has frames in the last category.

## Findings during implementation

1. **INET pitfall, found by A9.** `Chunk::removeTagsWherePresent<T>()` in INET 4.7 clears the tags of *every* type in the range (`SharingRegionTagSet::clearTags`).
   - The first strip implementation therefore also deleted the application's `CreationTimeTag`.
   - The effect was that the sink lifetime vectors became NaN, while the PCAPs stayed identical.
   - The fix (`faed3ae`) removes exactly the `TtTimestampTag` regions.
   - The self-test now checks that foreign tags survive tagging and stripping. With the old strip it fails 3/10 cases (checked by temporarily reverting the fix).
   - Consequence for later M2 work: any code that removes one tag type must not use that call.
2. **INET region tags are copied to every enclosing chunk level** on insertion, and peeking a sub-range can return an element chunk without the enclosing level's tags.
   - Tags must therefore live on the leaf chunks, as here.
   - The whole payload region must be replaced in one step, so that stale copies of the tag at the enclosing level do not survive stripping.
3. **N3 fragmentation** splits the tagged chunk into slices, each carrying the tag of its byte range (`SliceChunk.cc:35`); INET's reassembly merges them back into the original chunk (census: the far translator sees the whole `ApplicationPacket`). The test shows survival through IPv4 fragmentation and reassembly. It does not show behaviour for a component that rebuilds frames from raw bytes; none exists in this user plane (design limitation T7).

## Deviations from the approved design (`migration/m2-s0-design.md`)

| Design | Implemented | Why |
|---|---|---|
| Remove the payload, `dupShared`, add one tag, re-insert | One tag per payload *leaf* chunk (same values), with the whole payload region replaced in one `replaceDataAt` | INET copies region tags to every enclosing level, and a peek can return an element chunk without them (Finding 2). Recovery merges the regions and requires full coverage and one value (T5). |
| Per-frame values as vectors | Per-frame CSV logs (exact simtime strings, payload hash) plus counters as scalars | Exact (ps) joins to PCAP without float rounding. The layers' generic packet-flow statistics are not recorded. |
| A2 within 1 ns PCAP resolution | Exact to 1 ps (pcapng `if_tsresol` = 12), plus A2b (TT_in reception = station transmission + 50 ns) | The refinement: define the event and do not mask a boundary mismatch with a tolerance |
| Residence: TSN-port reception to the other translator's TSN-port *transmission* | TSN-port reception to the other translator's 5G-side-port *reception* (recovery event, verified to the ps) | The TX-path slot sits above the MAC queue, so transmission time is not seen there. TT_out's TSN-port PCAP time is still recorded for each frame. |
| Negative-control targets: noingress → UL A1; offset → DL A2 | noingress → UL A1–A4; offset → DL A2 and A4 | Declared in `omnetpp.ini` before running. With no UL tag nothing can be verified in A2–A4. A4 uses the carried ingress time, so the +1 ns shows there too, as exactly −1 ns. |
| — | Added: `M2S0-probe*` structure census; synthetic self-test; `M2S0-load-off` and `M2S0-load-harq16`; loss attribution by RLC replay; audit on the stations' TX path as well | The refinements (structure first, separate loss accounting) and the decision on 16 HARQ processes as a control |

## What M2-S0 does not show

- **No gPTP correction.** No `correctionField` is written, and there is no transparent-clock or residence-time correction. The tag is read and verified, never applied.
- **Simulation time only.** Translator clocks are not modelled (T8).
- **Not a 3GPP-faithful carriage (T1).** The tag is never serialized; N3 and the radio do not carry the bytes a real 5GS would.
- **Untested live:** frames with `EthernetPadding` (they occur only below 64 B), and structures other than the census. Those stop the run with an error and were covered by the synthetic self-test only.
- **Single configuration:** one gNB and one UE, numerology 0, the M1 traffic.
