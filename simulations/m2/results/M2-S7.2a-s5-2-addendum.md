## 2. RNG independence audit (RD-3)

### 2.1 Method

**Static, on OMNeT++'s own resolution** of each generated configuration (`opp_run -q runconfig`, effective entries). Tool: `check/m2s72_rngaudit.py`.

Semantics are taken from the OMNeT++ 6.5.0 sources:

| Rule | Source |
|---|---|
| A module's local RNG k maps to the physical RNG of the **first** `<pattern>.rng-k` entry whose pattern matches its full path, else to physical RNG k | `crngmanager.cc` |
| Physical RNG j is seeded with `seed-j-mt` if it is given, else with **seed-set × num-rngs + j**. So an unseeded RNG changes with `num-rngs`, i.e. with N | `cmersennetwister.cc` |
| Patterns: dotted-path, full-string, case-sensitive; `[a..b]` after a literal is a numeric range; a numeric range consumes the whole digit run | `patternmatcher.cc` |

**Cross-check of the matcher.** The Python port is checked against OMNeT++'s own `PatternMatcher`, compiled from `fixtures/omnetpp_pattern_xcheck.cc` against the 6.5.0 `liboppcommon`.
- 4230 pattern × path pairs: every `rng-` pattern of `omnetpp.ini`, `m2s72.ini`, `m2s72s5.ini` and the proposed mixin, plus edge cases, against the full N = 8 module inventory.
- 282 match. **0 disagreements.**
- The table is committed (`fixtures/omnetpp-pattern-xcheck.tsv`) and re-checked by a test.

**Draw call sites.** Taken from the Simu5G `v1.8.1` (`7477d266`) and INET `v4.7.0` (`dfe270b2`) sources, read only:

| Module (per run) | Draws | Physical RNG today |
|---|---|---|
| scheduler tie-break / jitter: MAXCI equal-score coin flip (`LteScheduler.h:43`), QoS-PF ±ε/2 jitter (`QoSAwareScheduler.cc`), PF jitter | per scheduling decision with candidates | **0, direct** (`getEnvir()->getRNG(0)`: no mapping can move it) |
| BLER table (`PhyPisaData` constructor) | once at start-up; count independent of N | 0, direct |
| gNB NIC: `mac`, `phy` (`randomChannelIndex_`), **one** `channelModel[0]` for every UE's UL reception, fading, shadowing | per UL reception of **any** UE | 0 (unmapped) |
| UE k NIC: `nrMac` (random access), `nrChannelModel[0]` (DL reception success, Jakes fading, shadowing; defaults `shadowing = true`, `fading = true`, `JAKES`, `dynamicLos = false`), `nrPhy`; LTE leg `mac` / `channelModel[0]` | per frame **addressed to UE k** (`PhyUe::handleAirFrame` deletes frames for other UEs before the channel model) and per feedback computation | 0 (unmapped) |
| clocks: GM / slave oscillators, TT clocks (E-all) | only with random-drift / noisy clocks (C-a: `ConstantDriftOscillator`) | 1, and 2k / 2k+1 per slave / DS-TT k ≥ 1 |
| traffic sources (`listener.app[j]`, `talker[k].app[j]`) | none: constant interval and length. **Checked** on the effective values; a random expression would make them consumers | 0 |

### 2.3 Controls for reproducibility, as implemented

1. RA-1 / RA-2 / RA-4 on every configuration of a batch, from OMNeT++'s resolution, recorded before the batch. A FAIL of RA-1 or RA-2 stops the batch.
2. Replication: **5 paired seeds** (RD-3) for every stochastic comparison. With R-4 / R-5 in force there is no basis for reducing replication at N > 1.
3. Numerical repeatability (one same-seed rerun per batch, PCAP / per-frame log hashes): unchanged (plan §2, item 4).

### 2.4 Proposed control: per-UE stream isolation (decision S5-2-D1; not generated)

`m2s72_rngaudit.py isolation-mixin` gives the following mapping, which is fixed for every N ≤ 8:
- UE k's NIC → physical RNG 16 + k;
- the gNB NIC → RNG 24;
- `num-rngs = 25`, with explicit seeds `j00${repetition}` for every j ≥ 2.

Statically, it makes **every** drawing module of UE k's NIC INVARIANT across N:
- 0 COUPLED in every audited pair, against 6–21 COUPLED as configured;
- the clocks are unchanged;
- only the four MULTI-UE modules stay shared.

What it would and would not achieve:
- **Would:** differences in UE k's metrics across N could no longer come from stream interleaving. They would come from contention (scheduling, the shared UL channel model and the tie-break), which is what E1 asks about. It also gives common random numbers across N (paired realisations).
- **Would not:** remove the tie-break or gNB randomness, or replace replication.
- **Costs:**
  - a new mixin in the generator, so new configurations, verified by regeneration / T0 as usual;
  - realisations no longer comparable with CP2 B / H runs. No Stage 5 comparison uses those runs.
  - E0v core keeps its accepted E0 identity, so the mapping would apply to **E0v-N and E1** only.
- **Recommendation:** adopt it for E0v-N and E1 together, before either runs.

### 2.5 Empirical audit (prepared, not run): design stage 7 / RD-3

`TtSyncMonitorRngProbe` (S7.1, default-off) records the numbers drawn per physical RNG. The S7.1 method (one RNG group varied at a time over seeds 0–4) is applied at N = 4 (Block F), with and without the mixin.

It answers:
- which streams actually draw at N > 1;
- whether UE k's metrics change when only another UE's stream varies.

It is a diagnostic campaign: it needs its own authorisation and is not part of this increment.

## 3. Per-UE measurement specification (E0v-N, E1)

### 3.1 Principle

- Every measurement is **per UE**.
- Across-UE results are **distributions**: min, max, spread, the worst UE and Jain's index. The system aggregate is reported **beside** them, never instead.
- +∞ marks "not delivered by T_end". It ranks above every delivered value and is never dropped (the S7.1 / E0 rule).

Implementation: `check/m2s72_peru.py`, pure functions over the observation record documented in its header.

### 3.2 Metrics (all performance, never gates)

| Group | Per UE k | Source (adapter) |
|---|---|---|
| Offered / achieved rates | DL and UL offered and achieved bit rate over [2 s, T_end); per-second series; service ratio achieved / offered | DL: gNB RLC TX `rlc-um-<n_k>-1.tx` SDUs → UE RLC RX `ue[k]…nrRlc-um-1-1.rx` deliveries. UL: `ue[k]…nrRlc-um-1-1.tx` → gNB `rlc-um-<n_k>-1.rx`. Load SDUs > 1000 B (the E0 filter). RLC level, because the PCAP recorders capture gPTP only |
| Bearer service | DL grant bit rate, grant bytes per LCID, TTI share, candidate TTIs, candidate-not-granted TTIs and share, MAXCI ineligible | gNB MAC log: grants of node n_k; `dl_sched` candidacy |
| H-ARQ | inserts, feedback, NACKs, feedback delays; occupancy at TTI start and peak within TTI, in log order, carried through TTIs without events; TTIs with all processes busy | gNB MAC log + attribution rule A-1 (§3.3) |
| Packet delivery | per-UE Q8 fate of every cohort Sync (used, delivered, lost, censored, invalid, late, UNEXPLAINED); P(used) | `Q8(ev, mlog, opt, k, attr="exclusion")`: the accepted class with the strict shared-TTI attribution (E0 r2 / P1) |
| Deadline outcomes | Sync residence NW-TT rx → DS-TT k tx: p50 / p99 / max; Follow_Up lag p99; counts above 5.5 ms and above one Sync interval | same |
| Clock synchronisation | slave k: max \|e\| between steps (steady state), largest update gap, update count | `ev.E[k]` of the accepted Block B evaluation |
| Load-DRB state | replayed RLC TX backlog per 0.5 s, sustained growth (E0 rule [A]), accounting | `replay_um` / `G.deliveries` for UE k |

### 3.3 H-ARQ attribution rule A-1 (per UE at N > 1)

The gNB MAC log names the UE on an H-ARQ **insert** line ("for node with id n") but **not** on a **feedback** line ("feedback received for process p codeword c"). Process ids are per UE.

- **A-1a:** a feedback line is attributed to UE u when u is the only UE with process (p, c) open (inserted, not yet fed back) at that point of the log.
- **A-1b:** if several UEs have it open, the feedback goes to the one whose open insert lies exactly d* before it. d* is the single feedback delay of every A-1a attribution in the run. If the A-1a delays are not one value, there is no d* and A-1b is not used.
- **Otherwise the line is AMBIGUOUS.** A feedback line with no open candidate is ORPHAN, and an insert into an open process is RE-INSERT.
- Per-UE occupancy is produced **only** when ambiguous = orphan = re-insert = 0. Otherwise it is NOT EVALUATED, never estimated.

### 3.4 Correctness of the per-UE evidence (gates of a per-UE evaluation)

| Row | Rule |
|---|---|
| PU-1 | every expected UE has an observation record with its own, distinct node id |
| PU-2 | per UE: every cohort Sync has exactly one fate; UNEXPLAINED = 0 (the Q8 rule per UE) |
| PU-3 | per loaded UE: load-DRB destroyed = unexplained = observed-not-predicted = 0 (1.8.1: no deletion) |
| PU-4 | H-ARQ attribution complete: ambiguous = orphan = re-insert = 0 |
| PU-5 | conservation of attribution: per-UE DL grant bytes and H-ARQ inserts sum to the run totals |
| AV-1 | per UE: Q8's internal consistency (tunnel, SDU-to-frame mapping, replay model) |
| AV-2 | per UE: observed load = declared placement, DL and UL |
| AV-3 | per UE: DL and UL RLC vectors present (missing → NOT EVALUATED, which is not a pass) |

**Adapter validation: a dependency, done read-only, no new simulation.**
- **What can be tested here:** the adapter that reads raw outputs (`m2s72_peru_adapter.py`) cannot be tested without real N > 1 1.8.1 output. Only its log parser is tested here.
- **Validation step:** `check_m2s72_s5n.py adapter-validate`, run on the CP2 rev. 2 runs the VM keeps:
  - `M2S72-H16-q0-Ca-n4` and `M2S72-H16-q0-Ca-n2`, with DL and UL load declared on UE 1;
  - `M2S72-B-q0-Ca-n4`, with no load.
- **Pass condition:** every PU / AV row PASS, in two parts:
  - **Part A** (gPTP, RLC and clock evidence: PU-1, PU-2, PU-3, AV-1, AV-2, AV-3) is checked on these CP2 runs.
  - **Part B** (PU-4 H-ARQ attribution and PU-5 grant conservation) needs the gNB MAC log, which the CP2 runs do not record. There, PU-4 and PU-5 are NOT EVALUATED. Both stay gates of **every** E0v-N run, which records the MAC log, so an incomplete attribution still fails that run.
- **Until then:** `check_m2s72_s5n.py run` **refuses** E0v-N (exit 2) unless `S5N_ADAPTER_VALIDATED` names the reviewed validation record (decision S5-2-D2). `check_m2s72_s5v.py` (N = 1) still refuses E0v-N.

**Expected first finding.** Whether the UL RLC vectors exist at the names above is unverified. If they do not, AV-3 reports it, and the UL source is decided at review. Nothing is guessed.

| Class | Rule |

## 4. Adaptive E1 capacity selection (RD-2): `check/m2s72_e1sel.py`

**Ladder** (plan rev. 1.1): 0.5, 0.8, 1, 1.25, 1.6, 2 (exact ns intervals at every N).

**Outcome of one bracket run** (seed 0, from the per-UE evaluation):

| Outcome | Meaning |
|---|---|
| ok | no UE overloaded or starved; gates PASS |
| overloaded | some UE overloaded |
| starved | no UE overloaded but some UE starved (a scheduler effect, not a capacity limit; it bounds f_E1 all the same) |
| invalid | a gate FAIL, a non-OK run outcome or a not-evaluable class. Never a capacity result |

**Bracket per combination** (option × placement × N × HARQ):

| Rule | Content |
|---|---|
| B-1 | start at 1.0. With the HARQ5 economy, if approved (plan §4.3), start at the HARQ16 f_lo of the same (option, placement, N) |
| B-2 | step up after ok, down after non-ok. When f_lo (ok) and f_hi (non-ok) are adjacent, **one confirmation run above f_hi** (E0 [A] escalation rule) |
| B-3 | an ok above a non-ok is **NON-MONOTONE**: stop for review, no f_lo |
| B-4 | ok at 2 → f_lo = 2, f_hi unknown (never extrapolated). Non-ok at 0.5 → no f_lo → STOP |

Typically 3–4 runs per combination.

**Selection:**

| Rule | Content |
|---|---|
| S-1 | f_E1 = the largest ladder factor ≤ (1 − m) × **min over combinations of f_lo**. f_lo, not f_hi, is used as the conservative measured bound. Any combination without f_lo, or no ladder factor below the limit, means **STOP** (no fallback, RD-2) |
| S-2 | **m = 0.20 is a candidate, not a guarantee:** f_E1 is reported for m ∈ {0.10, 0.20, 0.30}, with the binding combination |
| S-3 | the margin is validated by the verification runs, not by the margin itself |

**Verification** (E1 entry gate; every E1 loaded configuration at f_E1, seeds 0–4, every UE):

| Check | Rule |
|---|---|
| V-1 | no UE overloaded |
| V-2 | no starvation class |
| V-3 | every loaded UE achieved ≥ 0.99 × offered, DL and UL |
| V-4 | all gates PASS |

Any failure stops E1, and the (configuration, seed, UE, class) is reported. These runs are E1's loaded runs at f_E1 (plan §4.3: evaluated once as the gate and reused as data).

**Why per-UE matters here.** A system-wide criterion can pass while one UE starves. Under MAXCI the best-channel UE can absorb the capacity, for example a near UE in `sym` at N = 8, where UEs stand at different distances. The overload and starvation classes are therefore evaluated per UE, and the bracket stops on the **first** UE affected.

**Dependency:** this needs real E0v-N outcomes. The state machine and selection logic are tested on synthetic outcomes, so the procedure is fixed before any number exists. The runner mode that drives it is the next increment (§7).

## 5. How the measurements separate the mechanisms (methodology)

Every comparison changes **one** configured factor (RD-4, verified by configuration diff on OMNeT++'s resolution). It is evaluated per UE with paired seeds, and it attributes a difference only to a mechanism whose **own observable** moved.

| Mechanism | Comparison that isolates it | Discriminating observables (per UE) | Confound handled by |
|---|---|---|---|
| **Scheduling discipline** (MAXCI vs QoS-PF) | Q-0 → **Q-0p** (same shared DRB, equal profiles) | grant order and share, candidate-not-granted share, TTI share, Jain index; residence of gPTP on the shared DRB | QoS-PF jitter and MAXCI tie-break both on RNG 0: 5 paired seeds; the tie-break count is reported, not removed (R-5) |
| **Bearer mapping** (shared DRB vs a dedicated gPTP DRB at equal priority) | Q-0p → **Q-de** | gPTP residence and lag vs the load DRB's backlog of the same UE; per-DRB grants | priority held equal (`nasc-be`); verified ISOLATED |
| **Bearer priority** | Q-de → **Q-d** | the same, plus grant order between the gPTP and load DRBs | mapping held equal; verified ISOLATED |
| **H-ARQ limitation** | HARQ16 vs HARQ5, same option, N, placement and factor | per-UE occupancy (A-1), TTIs with all processes busy, candidate-not-granted TTIs, MAXCI ineligible, service ratio, backlog growth. A HARQ effect is claimed only if all-busy TTIs rise **and** service falls in the same UE (RD-1: measured, no 5/6 assumption) | 1.8.1: deletion throws (Q8-v), so a reduction is a service effect, never silent loss |
| **Multi-UE contention** | N at constant per-UE load (`one0`: UE 0's load fixed) and constant total load (`sym`: L_tot split); unloaded UEs of `one0` | per-UE residence, P(used), ST-gptp on **unloaded** UEs; grant share of the loaded UE vs N; across-UE spread | per-UE base flows grow with N (reported per N); stream shift (R-4): with the isolation mixin (D1) UE k's NIC realisation is fixed across N, else it is a declared confound |
| **Capacity / overload** | factor ladder within one combination (E0v-N) | per-UE sustained growth and achieved < offered; the first UE affected | bracket monotonicity (B-3) |
| **Clock / servo** (H-S1) | load vs idle at the same N | max \|e\| per slave vs update gaps and lag | the exact oracles (M2 / M3 / M3d / M4) are gates: a model error can never be read as a performance result |

**Claim scope.**
- Results hold for this simulator, Simu5G 1.8.1 (unmodified), one cell and the positions configured.
- A difference between options is reported only where the paired-seed intervals separate (the S7.1 interval rule).
- A mechanism is named only when its own observable moves in the same UE.
