## Research briefing

**1. What we learned**
- Under re-evaluation of the existing outputs against checks declared beforehand, the one-line correction of upstream v1.8.0 `LteSchedulerEnb.cc:403` passes every check:
  - it restores the QoS-aware uplink;
  - it conserves UL SDUs and bytes exactly;
  - it reproduces the uncapped MaxCI scheduler's event, message, module and log content exactly;
  - it leaves DL and gPTP correctness unchanged.
- The two original failures were check-definition errors. Both now pass under criteria fixed before the outcome:
  - the eventlog offset metadata;
  - the arbitrary 0.5 MB bound. The UE queue now equals the Q-0 reference exactly: 368 SDUs, 516,161 B.
- The strict exclusion rule resolves every shared-TTI HARQ-5 loss in the P1 evidence. It fails closed in each of six deliberately ambiguous, inconsistent or under-evidenced cases.

**2. Why it matters scientifically**
- On Simu5G 1.8.0, any Q-d result that depends on UL service measures a scheduler defect, not a QoS behaviour. The approved E2 baseline is therefore DL-only in both options.
- Multi-UE reliability accounting can stay packet-level and evidence-based. That makes HARQ-5 multi-UE experiments evaluable without new instrumentation, as long as each TTI's alternatives can be excluded positively.

**3. What remains unproven**

| Topic | Status |
|---|---|
| The fix's generality | Untested: DRR (also capped), multi-codeword, DL idle backlog, N > 1, other seeds |
| Existing upstream issue | No matching commit after v1.8.0 on `master` (`466f9a96`, fetched 2026-11-03), and web search found nothing. **GitHub issue / PR search was not possible here**, so it must be checked by hand before submission |
| The attribution rule | Validated on one N = 2 HARQ-5 run. d ≥ 2 deletions per TTI and N > 2 do not occur in data |
| UL interference and bidirectional dependability | Outside the approved DL-only E2 |

## Part C — E2 DL-only protocol (design only)

The protocol is `results/M2-S7.2a-e2-protocol-draft.md`.

**Design:**
- Matched Q-0 / Q-d runs with **UL load disabled in both**.
- Adaptive factors 0.8 / 1.0 / 1.1 / 1.2 / 1.3 / 1.5 / 2.0 × L_tot, bracketed per N, placement and option, then limited bisection and replication.
- No N = 1 threshold assumed at N > 1.
- A 4-run DL-only N = 1 re-baseline against E0.
- HARQ5 pairing evaluated with the strict rule.
- Upper bound ≈ 210 runs.

**Explicitly cannot establish:** UL interference, UL timing, or bidirectional dependability.

**Unchanged:** the E0 UL-loaded results.

**Implementation still required before any run (Python only, not done):** UL factor 0 in the generator, with tests and exact verification; DL-only configs; a "no UL load" CFG check.
