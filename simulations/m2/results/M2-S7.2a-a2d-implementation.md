### 2.1 Architectural decisions

| Decision | Reason |
|---|---|
| **No Simu5G change; no C++ or NED change.** NACK injection uses the upstream `IdealChannelModel` exactly as A2-V1 did; scheduler evidence uses the upstream `rtxAcid` log line. | Requirements 2, 5 and 6. **No architectural blocker:** both needs are met by configuration alone. |
| Hand-written `m2s72a2d.ini` that includes `m2s72s5.ini` unchanged, rather than a generator section | As `m2s72a2v.ini`. The generators and their outputs stay byte-identical, and the configuration is reviewable line by line. |
| The A2-V1 base (`M2S72-E0vN-q0-one0-n2-f1`) | Comparability with A2-V1-S1, the only genuine NACK record, and with the accepted N = 2 smoke |
| NACK injection on **every** UE | DR-07a demands NACK chains on more than one UE and multi-NACK groups. A multi-NACK group needs two UEs NACKing on the same process in the same TTI, impossible with A2-V1's single lossy UE. |
| `perDl = 0.3`: **a proposal (A2-D1)** | A2-V1's 0.1 gives a discard probability of 1e-4 per transport block (it recorded 0 discards). The value is a design parameter, not a prediction. The run decides the minima (protocol §2.1). |
| Loss process on its own RNG 4, seed `400<repetition>` | Deterministic and identical in both twins. No other module's draws change: the twin differs only in logging (R-1). |
| Twin comparison built on the **accepted** E0 comparator, plus a filtered console-log comparison | It reuses the reviewed non-perturbation rules, and adds the stronger check that every non-scheduler log line is equal |
| Evaluation with the **accepted** `check_m2s72_a21.py --contract full`, unchanged | The A-2.1 verdict is never re-implemented. The coverage check reads its record only. |
| Names refused by the WP-A1 and A3 tooling | A diagnostic can never be an E0v-N campaign run. Its counters live in their own record. |
| No runner; the protocol's commands plus `plan` | The run is V-6, an independent execution. No development-agent run path exists to misuse. |
