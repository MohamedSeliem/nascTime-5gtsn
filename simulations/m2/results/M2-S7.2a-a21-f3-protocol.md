| E-4 | The `par … ue[k].cellularNic.nrMac macNodeId` values in the sealed `.sca` are {0: 2049, 1: 2050}. | 11 |

Declared facts checked at E-6:
- **F-1:** one insert of MAC PDU 145933, at 361 ms, on process 0 / codeword 0, for node 2050.
- **F-2:** transmissions of 145933 at exactly 361, 367, 373 and 379 ms.
- **F-3:** `PDU 54326 set for RTX` at exactly 366, 372 and 378 ms, and no discard of 54326.
- **F-4:** gNB NACK feedback on process 0 at 366, 372 and 378 ms, and ACK at 384 ms.
- **F-5:** "process 0 has been selected for retransmission" at 367, 373 and 379 ms.
- **F-6:** the main-loop markers are balanced.

The following are recorded but not asserted:
- the number of scheduler-module and `rtxAcid` lines (expected 0);
- the UE-side receptions of 145933;
- any insert or extract whose MAC id happens to equal 54326;
- the line count per module.

The fixture's final names are written only after E-7 passes:
- `a2v1-first-chain.log.gz` (`gzip`, mtime 0, so it is reproducible);
- its `.sha256` pin;
- `a2v1-first-chain.meta.json`, which records the source paths and hashes, the seal and manifest hashes, the node ids, the boundary, the first, last and first-excluded lines, the decompressed sha256, the declared and found facts, the read-only wrapper verdict, and the script's sha256;
- `steps.txt`;
- `SHA256SUMS` of the output directory.

If any step stops, the extractor writes `FAILED.txt` (exit code and reason). Copied bytes keep the name `*.partial`. Nothing is retried, renamed or deleted.

### Deviation: where the fixture ends

Your wording was "through the complete final feedback group and its closing main-loop boundary". The cut is therefore placed at the end of the **TTI** of that closing loop, not directly after its END marker.

Simu5G processes a TTI's feedback events after that TTI's main loop. Cutting right after the END marker would split a TTI: units that are due feedback in that TTI would be left open. X-14 shows this on the reconstruction. Ending at the END marker makes A2-2 fail ("OPEN at the end in state WAIT"); the TTI-complete cut gives the declared rows. A TTI-complete cut is also how a simulated-time limit ends a log.

### Commands on the VM

Run these on the VM by hand, in a fresh clone. Paths outside `/mnt/nasctime-results` are examples.

```bash
# 0. fresh clone of the reviewed bundle; record the head and the extractor's hash
cd ~/review && sha256sum -c SHA256SUMS
git clone -q -b m2/s72a-a21 a21-f3-full.bundle a21-f3 && cd a21-f3
git log -1 --format=%H                                     # = the head named in IMPORT.txt
sha256sum simulations/m2/check/m2s72_a21_fixture.py         # = 01884f94…700b (§1)

# 1. the seal's sha256 AS RECORDED when A2-V1 was sealed (from your A2-V1 lifecycle record)
SEAL=<64 hex digits>
sha256sum /mnt/nasctime-results/a2-nack-1-evidence.sha256   # independent look; must equal $SEAL

# 2. the one extraction attempt
OUT=$HOME/a21-f3-fixture-$(date -u +%Y%m%dT%H%M%SZ)
python3 -I -B simulations/m2/check/m2s72_a21_fixture.py extract \
    --results-root /mnt/nasctime-results --seal-sha256 "$SEAL" --out "$OUT" 2>&1 | tee "$OUT.console.txt"
echo "rc=${PIPESTATUS[0]}"                                  # 0 expected; anything else: STOP (§4)

# 3. independent audit of the result (read-only)
(cd "$OUT" && sha256sum -c SHA256SUMS)
(cd /mnt/nasctime-results && sha256sum -c --quiet a2-nack-1-evidence.sha256) && echo "seal still verifies"
N=$(python3 -I -c 'import json,sys; print(json.load(open(sys.argv[1]))["extraction"]["bytes"])' "$OUT/a2v1-first-chain.meta.json")
LOG=$(python3 -I -c 'import json,sys; print(json.load(open(sys.argv[1]))["sources"]["log"])' "$OUT/a2v1-first-chain.meta.json")
cmp <(zcat "$OUT/a2v1-first-chain.log.gz") <(zcat "$LOG" | head -c "$N") && echo "fixture = byte-identical prefix of the sealed log"
zcat "$OUT/a2v1-first-chain.log.gz" | grep -nE '\(id 145933 \)|PDU 54326 |ENB MAIN LOOP' | tail -20   # eyeball the chain and the cut
```

**About `--seal-sha256`.** The runner does not write the seal file's own hash anywhere, so the value must come from the record you made when A2-V1 was sealed. If no such record exists, **stop** and decide.

The alternative is to take the value now with `sha256sum` and enter it in the review record as "recorded at F3, not at sealing". It then pins the seal only against changes during the extraction. Inside the seal, every sealed record and the raw-output manifest are still checked.


The run uses the following inputs:
- **Window:** the whole prefix (t0 = 0).
- **Grants:** parsed from the fixture by `m2s72_maclog`.
- **Node ids:** from the metadata (taken from the sealed `.sca`).
- **Processes:** from the configuration name.
- **No `.sca`:** the run's scalars cover the whole run and don't describe a prefix, so A2-8 is NOT EVALUATED.

## 4. Stop conditions

- **Phase 1:** any exit other than 0, any `FAILED.txt`, a failing independent audit (step 3), or a seal that no longer verifies. In each case, stop and report without a second attempt. A new attempt needs a new decision and a new `--out`.
- **Phase 2:** exit 3 (inputs refused) or 1 (a deviation from R-1…R-10). In each case, stop and report the record unchanged. Never adjust an expectation, a fixture or a row after seeing it. A PENDING test is never a PASS.
