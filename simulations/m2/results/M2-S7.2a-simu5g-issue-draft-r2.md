**Title:** `scheduleGrant`: a capped grant marks a still-backlogged connection inactive (`LteSchedulerEnb.cc:403`). Under `QOS_PF` the UE uplink is served once per BSR, including in `simulations/nr/standalone_drb`

## Summary

`LteSchedulerEnb::scheduleGrant` computes the remaining queue against the **already decremented** `toServe`:

```cpp
toServe     = (uBytes > toServe) ? 0 : toServe - uBytes;
queueLength = (uBytes > toServe) ? 0 : queueLength - uBytes;   // line 403
if (toServe == 0) { stop = true; if (queueLength == 0) active = false; break; }
```

**What goes wrong.** When the grant is capped (`bytes` smaller than the backlog):
1. `toServe` reaches 0;
2. line 403 then sets `queueLength = 0` although backlog remains;
3. the connection is reported `active = false`;
4. `QoSAwareScheduler` erases it from the active set;
5. in UL it returns only with the next BSR, so the UE gets one transport block per SR/RAC → BSR cycle.

**Who is not affected.** Uncapped callers such as `LteMaxCI` (which passes `UINT_MAX`) are unaffected.

## Proposed patch (one line; `git apply --check` passes on `master` `466f9a96` and on v1.8.0)

```diff
--- a/src/simu5g/stack/mac/scheduler/LteSchedulerEnb.cc
+++ b/src/simu5g/stack/mac/scheduler/LteSchedulerEnb.cc
@@ -400,7 +400,7 @@ unsigned int LteSchedulerEnb::scheduleGrant(MacCid cid, unsigned int bytes, bool
             // update the counter of bytes to be served
             toServe = (uBytes > toServe) ? 0 : toServe - uBytes;
-            queueLength = (uBytes > toServe) ? 0 : queueLength - uBytes;
+            queueLength = (uBytes > queueLength) ? 0 : queueLength - uBytes;
             if (toServe == 0) {
```

The new value is the pre-grant backlog minus the booked bytes, floored at 0. Nothing else changes.

## Not tested (stated explicitly)

| Case | Status |
|---|---|
| **DRR (`LteDrr`)** | Also passes a capped value (`desc.deficit_`), so it is likely affected; not run |
| **Multi-codeword grants** | The next codeword's `queueLength` may also be under-stated (`:314`); not exercised |
| **More than one UE** | Capped grants become routine with quota splitting; not measured |
| **DL with idle backlog** | Every new DL SDU re-activates the connection (`LteMacEnb.cc:760`). A backlogged DL connection without new arrivals under a capped scheduler is unmeasured. Our runs show 0 DL deactivations when an SDU arrives in every TTI, even with 11,020 capped DL grants |
| **`scheduleGrantBackground` (`:733–738`)** | Sets `active = false` whenever `toServe` reaches 0. A different path; not examined |
| Other | Other numerologies, carrier aggregation, D2D, other seeds; not run |
| **Regression suite** | The upstream fingerprint suite was not run on the patched build |
