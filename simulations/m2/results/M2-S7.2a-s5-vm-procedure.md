## 4. G0 comparison (read-only; seconds)

The tool reads the committed 6.4.0 records from the S5 worktree. Those records are identical to `2586bce`'s.

For the M1 checker outputs, put copies under these names in one directory:
- your V1 outputs `v181-s5.txt`, `s5e.txt`, `s5i.txt`;
- the three `--mutate` outputs, as `v181-s5-mutation.txt`, `s5e-mutation.txt`, `s5i-mutation.txt`.

```bash
mkdir -p $V/g0/m1x && cp <dir of your V1 outputs>/{v181-s5,s5e,s5i}.txt $V/g0/m1x/
cp <your v181-s5 --mutate output> $V/g0/m1x/v181-s5-mutation.txt     # likewise s5e-mutation.txt, s5i-mutation.txt
python3 $S5/simulations/tools/g0_env_equivalence.py selftest --ref $S5/simulations/results/simu5g-1.8.1   # 9 / 9 PASS
python3 $S5/simulations/tools/g0_env_equivalence.py compare --ref $S5/simulations/results/simu5g-1.8.1 \
    --m1 <V1 NASCTIME_RESULTS_ROOT, e.g. ~/r181vm/m1> --m1x $V/g0/m1x \
    --m2 <V2 root given to run_r181c.sh, e.g. ~/r181vm/m2> \
    --cp1 $V/cp1 --cp2 $V/cp2/m2/M2-S7.2a-cp2r2/cp2r2-check.txt > $V/g0/g0-compare.txt; echo rc $?
tail -3 $V/g0/g0-compare.txt
```

**Exit codes:**
- 0: G0-V holds;
- 1: a verdict differs (G0-V does not hold);
- 3: records missing.

**Expected:** `G0-V verdict identity: HOLDS EXCEPT 1 ATTRIBUTED DIFFERENCE(S) (G0-R1; historical verdict kept)`. Every `G0-N` number difference is listed in the appendix and needs an attribution in the G0 record.

**Send back:**
- `g0-compare.txt`;
- the `regen.txt` files of §2 and §3;
- `$V/cp1/g0r1/verify-eff.txt`;
- `cp2r2-check.txt`;
- the `env*.txt` / `stack.txt` of each stage;
- `git -C $S5 status --short` and `git -C $CPW status --short`, both empty.

Your M1 / M2 VM records themselves are already in your hands. The G0 record (`simulations/results/simu5g-1.8.1/g0env/`) is completed from these files.

## 5. Smoke run E0v-q0-f1 (PREPARED — do not execute until authorised)

**Preconditions:**
1. §2 as expected;
2. §3 CP1 / CP2 as expected;
3. §4 G0 compared and the G0 record reviewed;
4. your explicit authorisation of the smoke run (D-3);
5. ≥ 6 GB free on the filesystem of `$V`. The runner's own rule stops below 4.35 GB: 1.5 × 0.9 GB + 1 GB + 2 GB.

**Purpose:**
- the first reviewed 1.8.1 MAC-log grammar census (MG-1);
- the run's raw size and wall time on the VM;
- one end-to-end pass of the lifecycle on real output.

It is not an E0v result (protocol §9).

**Dedicated results directory:**
- `$V/smoke-1`, new and used for nothing else;
- the stage is `$V/smoke-1/m2/M2-S7.2a-s5smoke`;
- a second smoke run needs a new root, for example `smoke-2`; the runner refuses an existing stage.

```bash
export NASCTIME_RESULTS_ROOT=$V/smoke-1
export S5_ENV_DECISION="D-2 2026-11-15 12:58: OMNeT++ 6.5.0 / INET 4.7.0 / Simu5G 1.8.1; G0 record <commit>; CP1/CP2 <commit>"
unset S5_RECORDS_REPO                       # ignored by smoke anyway; smoke never commits or deletes
$S5/simulations/m2/m2s72s5.sh smoke 2>&1 | tee $V/smoke-1-console.txt; echo "exit ${PIPESTATUS[0]}"
```

**What it does,** one simulation:
1. free-space rule;
2. `M2S72-E0v-q0-f1`, seed 0, 12 s simulated, non-express, MAC logs through `gzip -n`; 60 min limit;
3. outcome (OK / SIM-ABORT / TIMEOUT / ERROR);
4. per-run check (E0 rows + Q8-v, SG-403, MG-1, digest);
5. manifest;
6. E0 quick proxy;
7. `controls-q8` (in memory);
8. raw outputs made **read-only**;
9. manifest re-verified;
10. ledger `held (smoke review …)`.

**Exit codes:**
- 0: clean;
- 3: free-space stop, nothing run;
- 5: a non-OK outcome; raw kept as tier B (gzip, verified), not deleted;
- 6: check / quick / controls / manifest not clean; every step is still done and recorded.

**Evidence retention:**
- Nothing is ever deleted, released or committed by this mode. `m2s72s5.sh release M2-S7.2a-s5smoke` is refused.
- Raw outputs: `$V/smoke-1/m2/M2-S7.2a-s5smoke/runs/`, uncompressed and read-only.
- Records: `.../records/`:
  - `env-smoke.txt`, `stack.txt`;
  - `runs.tsv`, `steps.txt`, `ledger.tsv`;
  - `M2S72-E0v-q0-f1.{console.txt, check.txt, digest.json, manifest.sha256}`;
  - the controls output inside `steps.txt`.

  Every record is fsync'd.
- Then make an independent copy of the records and check it:

```bash
cp -a $V/smoke-1/m2/M2-S7.2a-s5smoke/records $V/smoke-1-records-copy
(cd $V/smoke-1/m2/M2-S7.2a-s5smoke && sha256sum records/* > $V/smoke-1-records.sha256)
python3 $S5/simulations/m2/check/m2s72s5_lib.py verify-manifest \
    $V/smoke-1/m2/M2-S7.2a-s5smoke/records/M2S72-E0v-q0-f1.manifest.sha256           # "manifest verified"
```

**Expected,** reported for review, not as E0v predictions:
- outcome OK;
- Q8-v PASS;
- SG-403 (0, 0);
- F0-1 PASS (`M2S72-E0v-q0-f1` is declared loss-free).

**MG-1 is the open item:**
- the 1.8.1 grammar is not yet frozen;
- an UNCLASSIFIED line gives an MG-1 FAIL and exit 6;
- that is a review finding for the census, not a lost run.

**Send back:**
- `records/` (or the copy);
- `$V/smoke-1-console.txt`;
- the `du` lines at the end of `steps.txt`.

**Do not:**
- delete or compress the raw outputs;
- start `e0v`, `e0vp` or `e0vh5`.

The next step after review is a separate, reviewed commit that freezes the census into MG-1 and re-derives the E0v size and time estimates.
