## 1. The five corrections

| # | Review point | Correction | Test |
|---|---|---|---|
| 1 | hard-coded `--fingerprint=0000-0000/tplx` | **Removed.** The run does not request a fingerprint. No A2-V1 row uses one, and a dummy value would only print a "Fingerprint mismatch" line (OMNeT++ 6.5.0 still exits 0: N = 1 smoke protocol, `envirbase.cc:2156`, `cmdenv.cc:274`). Reproducibility rests on the manifest hashes and the pinned configuration. `env.txt` records `fingerprint: not requested`. The command line is otherwise the accepted runner's (`m2s72s5.sh:117`), with the new ini and name. | T-w-config-unchanged (no `--fingerprint` anywhere), T-w-complete |
| 2 | build failure only printed | The build is a **hard stop**: non-zero exit or no `libnasctime_m2.so` → rc **11**, no simulation, `build.log` kept. | T-w-build |
| 3 | baseline raw size and the storage limit | **Size:** the baseline raw size is the **sum of the N = 2 smoke's manifest sizes**, and it must equal the files on disk: same set, same sizes (`baseline-size`); any difference is a gate failure. The run is measured the same way: regular files under `runs/`, the run log included. **Limit:** L-3 = 2 × that size. It is **enforced during the run**: a watchdog measures `runs/` every 5 s and terminates the simulation (`timeout` forwards SIGTERM to its process group) as soon as the limit is exceeded. The outcome is then `STORAGE-LIMIT`, and `storage-limit.txt` is written. L-3 is also checked after the run. **Free space:** must be ≥ max(10 GiB, limit + 4 GiB) before the start. | T-g-baseline-size, T-w-storage, T-w-space |
| 4 | G-0 genuinely fail-closed | Every check below stops the wrapper **before the build and the simulation**, with rc **10**. A missing file or an unreadable input is a failure. The configuration check now compares against the **exact** declared set: nothing undeclared added, nothing declared missing, a complete dump required. It used to merely filter lines. | §2; T-w-*, T-g-* |
| 5 | preserve everything, never retry | Nothing is deleted on any path. Each attempt gets a fresh root, and the run root `a2-nack-1` is **refused if it exists**, whatever an earlier attempt left there; its content stays untouched. After the start, on **any** outcome: manifest, verification, `chmod -R a-w runs/`, lifecycle record and sealing hash. The simulator is started **once**; a lifecycle failure ends the wrapper with rc **20** and no evaluation. A new attempt needs a new decision. | T-w-env, T-w-simfail, T-w-timeout, T-w-storage, T-w-complete (a second invocation is refused) |

After the gates, the build runs (rc 11 on failure). `gate` mode stops there with rc 0.

**Exit codes of `run`:**

| rc | Meaning |
|---|---|
| 0 | lifecycle complete, evaluated, preserved evidence intact. **The scientific verdict is `eval/a2v1-*.txt`** (rc 0 = ACCEPTED). |
| 20 | lifecycle failure (L-1…L-4) |
| 21 | an evaluation tool errored (no scientific verdict) |
| 30 | preserved evidence changed during the run |

**Lifecycle success ≠ scientific success**, as in the review §7.

## 3. VM procedure

```bash
export OMNETPP_ROOT=/home/vboxuser/testing_nasc/omnetpp-6.5.0 INET_ROOT=/home/vboxuser/testing_nasc/inet-4.7.0
export SIMU5G_ROOT=/home/vboxuser/testing_nasc/simu5g-1.8.1
export A2V1_RESULTS_ROOT=/mnt/nasctime-results
export A2V1_COMMIT=<the full tip id of IMPORT-M2-S72A-A2D2-R1.md>
REPO=/home/vboxuser/testing_nasc/nascTime; W=/home/vboxuser/testing_nasc/nascTime-a2nack
git -C $REPO fetch origin m2/s72a-a2d2:m2/s72a-a2d2
git -C $REPO rev-parse m2/s72a-a2d2                                     # = A2V1_COMMIT
git -C $REPO worktree add --detach $W $A2V1_COMMIT
cd $W/simulations/m2
python3 -B check/test_m2s72a2v1_wrapper.py | tail -1                    # A2-V1 wrapper tests: 20 / 20 PASS (no simulation)
```

**Step A: gate dry run** (no simulation; it may run during the review):

```bash
./m2s72a2v1.sh gate; echo "gate rc $?"                                  # 0
ls -d $A2V1_RESULTS_ROOT/a2-nack-gate-*                                  # its records: records/gate.txt, steps.txt, p0/
```

**Step B: the single run** (only after explicit authorisation):

```bash
./m2s72a2v1.sh run; echo "run rc $?"                                     # 0
cat $A2V1_RESULTS_ROOT/a2-nack-1/records/{gate.txt,lifecycle.txt,wrapper-verdict.txt}
tail -3 $A2V1_RESULTS_ROOT/a2-nack-1/eval/a2v1-M2S72-E0vN-q0-one0-n2-f1_A2V1.txt
```

On a non-zero rc: **stop and report**. Do not rerun, and do not delete anything.

**Send back:**
- the gate root;
- `a2-nack-1/{p0,records,eval}`;
- `a2-nack-1-evidence.sha256`;
- the console lines.

The raw outputs stay on the VM, read-only, with their manifest.

**Expected:**
- gate rc 0;
- run rc 0: L-1…L-4 PASS, wall about 200 s, raw ≤ the limit;
- `a2` rc 0, `a2-controls` rc 0, `a2v1` rc 0, with NACK lines within 0.111 · N1 ± 3 √(0.111 · N1) (review §8).
