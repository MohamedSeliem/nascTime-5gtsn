## 5. The `controls` mode and its results

`check_m2s72_s5n21.py controls <runs> <cfg> <records dir> [--t0 <s>]`:
- **Isolation:** every mutation is applied to a copy of the run's evidence in a temporary directory, and the copy is evaluated exactly as `hrq` evaluates. The inputs are only read; consumed-input and code provenance are recorded.
- **Baseline guard:** a control counts only if its declared rows PASS on the unmodified copy. Otherwise it is NOT BUILDABLE, with the reason.
- **No vacuous controls:** a mutation that leaves the copy identical is a FAIL.
- **Result per control:** PASS, FAIL or NOT BUILDABLE, with the baseline, the mutation, the declared outcome and the observed rows.
- **Exit codes:** 0 every buildable control as declared; 1 any FAIL; 4 no *mutation* control buildable (the positive control and the NC-full-masquerade observation alone prove nothing); 2 refused or error.

Measured on the I-8 commit (synthetic runs):

| Run (synthetic) | PASS | FAIL | NOT BUILDABLE | Exit | Notes |
|---|---:|---:|---:|---:|---|
| N = 2, NACKs on UE 1, `.sca` from the generator truth | 22 | 0 | 0 | 0 | the 20 mutation controls, the NC-full-masquerade observation and the positive control PC-unmodified |
| N = 1 | 12 | 0 | 10 | 0 | the 9 controls needing a second UE ("needs N >= 2") and NC-full-masquerade (no retransmission) |
| N = 2 without `.sca` | 19 | 0 | 3 | 0 | the 3 scalar controls: no `.sca`, so their A2-8u baseline is not PASS |
| N = 2 without UE-side lines | 2 | 0 | 20 | **4** | PU-4h is NE without the reference, so every mutation control's baseline guard fails ("declared row(s) not PASS before the mutation"). The two passes are the positive control and the observation. |

An earlier rule counted those two as passes and exited 0 on that last run. The I-8 measurement exposed this, and the rule now counts mutation controls only; T-controls asserts exit 4.

## 8. Known limitations

### 8.1 Audit-hook input integrity (I7-R3)

- **Only Python-level opens are seen.** The tracker follows the "open" audit events of `open()`, `io.open` and `os.open`.
  - A file read by a C extension through its own system calls, by a subprocess, or through an inherited file descriptor is not recorded.
  - The accepted evaluators read their inputs through Python file objects or `gzip.open`; this was not audited for every code path of the s5n chain on a genuine tree.
- **Hash at first opening.** A consumed file is hashed when it is first opened. A change *before* that point is invisible to the tracker. The declared inputs (the log and the `.sca`) are therefore also hashed before anything reads them; other run files are protected only from their first reading onwards.
- **Only some roots.** The run directory, the fixture directory and `SIMU5G_ROOT` are tracked. Code is covered separately by the code provenance (I7-R2).
- **Cost.** Each consumed file is hashed twice. For the multi-gigabyte vector files of a genuine E0v-N run, this adds I/O proportional to their size.
- **The hook stays installed.** A Python audit hook cannot be removed; it is inert while no tracker is active, and only one tracker may be active.
- **The inventory is not integrity.** The size / mtime tree inventory is a labelled supplementary diagnostic. A same-size, timestamp-preserving change is detected only by the byte hashes (NC-provenance).

### 8.2 Other limitations

- **The s5n row contract is derived, not observed.** It comes from the accepted source (I7-R1). The first genuine E0v-N s5n run (V-N2 / the campaign) confirms it empirically. No committed record of a genuine E0v-N s5n row set exists.
- **`run` is tested with stand-ins.** The parts of s5n that need a complete simulation tree are replaced in memory by labelled deterministic stand-ins: Block B, I-2H, the adapter's observation and validation, SG-403, the grammar census and MG-1. `run_one`, its writer, the real `relabel`, the MAC-log reader and the A-1 rule run unchanged.
- **`controls` was exercised on synthetic runs only.** It was not run on the public fixture, whose layout is not a run tree, nor on any private run.
- **`hrq` / `hrq-fixture` are not staged.** Their records are written after the evaluation into a fresh directory; only `run` writes into a staging directory and renames it.
- **`run_one` accepts whitespace.** The accepted `run_one` accepts a whitespace-only `S5N_ADAPTER_VALIDATED`. The wrapper refuses it first, but `run_one` itself is unchanged.
- **V-N1 cannot declare "occupancy = A-1's".** The `hrq` record does not carry A-1's per-node occupancy. The equality with the XA truth is declared through PU-4o PASS with local EQUAL (the note in `vn1.expect.json` states this).
- **`SIMU5G_ROOT` is required.** The tests that run A-2.1 need it, as `test_m2s72_a21.py` does.

## 9. S5-2-D2 and `run`

- **S5-2-D2 is open.** No WP-A1 file sets, synthesizes or defaults `S5N_ADAPTER_VALIDATED`; T-no-d2-bypass checks this.
