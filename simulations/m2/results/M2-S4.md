# M2-S4: link-local gPTP Pdelay termination at the translators' TSN ports (results)

**Verdict: PASS.** All 55 rows of `M2-S4/check.txt` pass, including:
- the hard gate G0 (passive transparency);
- the 14 negative controls, each failing exactly its declared rows with the exact signature.

The M1, M2-S0, M2-S1 and M2-S3 regressions are unchanged (Regressions section).

**What changed.**
- **NW-TT `eth[1]`:** requester toward the grandmaster (and responder).
- **DS-TT `eth[1]`:** responder toward the slave.
- **No Pdelay frame crosses the 5G system any more.**
- **Mechanism:** the new `nasctime.m2.TtPdelayPort` module in the default-empty `trafficConditionerLayer` slot of each translator's TSN port, above the M2-S1 `TtTimestampLayer`.
- **What is untouched:** Sync and Follow_Up are not held, rewritten or corrected (correctionField 0); there is no residence-time correction and no second relay.
- **Unchanged software:** OMNeT++, INET and Simu5G are unchanged; no legacy code; no FRER.

**Main results** (`M2S4` seeds 0–9, frag, load, load-harq16):

| Measured by | Old: Pdelay forwarded end to end | New: link-local |
|---|---|---|
| Slave, raw D per exchange (PCAP) | 7.00005–17.76 ms (idle); 6.55–56.73 ms (load) | **50 000 ps exactly** |
| NW-TT, link to the GM | — | **50 000 ps exactly**, in every exchange |
| Slave's recorded `pdelay` | 7 000 050 ns first sample | **50 000 ps exactly**, every sample |

- **Exact agreement with PCAP:** every t1–t4 equals the PCAP first-bit time, and every wire timestamp equals floor_ns of it.
- **Rate ratio:** nRR is 1/1.
- **5GS clean:** zero Pdelay frames at NW-TT `eth[0]`, DS-TT `eth[0]`, UE `eth[0]`, UPF `dnEth` and N3 (inner GTP-U frames, after reassembly).
- **Robustness:** the same results hold under radio load and N3 fragmentation.

**Link delay is correct, the clock is not synchronized.**
- **After step 1 the slave is −(Lup + Res₁) behind,** about −5.0 ms (S2): there is still no residence correction.
- **Replay:** the M2-S3 slave model reproduces the slave exactly on every M2S4 run.
- **Offline composition check:** the composition planned for M2-S5 — cf' = NW-TT-measured link delay + Res, with the slave's **own** pdelay — predicts **0 ps**. In M2-S3, the same combination with the forwarded Pdelay gave +7 ms (NC-b).
- **Termination removes the double counting.** This is an offline prediction, not an applied correction.

**Scope of claims.**
- **Claimed:** link delay measured per TSN link at the TT ports (peer-to-peer), with first-bit PHY timestamps, ideal clocks and 1 Gb/s links with a 50 ns reference delay; Pdelay no longer crosses the 5GS.
- **Not claimed:**
  - synchronization;
  - rate-ratio validation (rr = nRR = 1);
  - one-way delay (U3);
  - wire fidelity;
  - IEEE 802.1AS-2020/Cor 1 or 802.1AS-2025 compliance (all clause pointers remain unverified, design section 7).

**Modules** (all in `src/nasctime/m2/`):
- **`TtPdelayPort`** (compound, `like ITrafficConditionerLayer`): `rx` and `tx` (`TtPdelayFlow`, `PacketFlowBase`) plus `engine` (`TtPdelayEngine`, no gates).
  - The `rx` flow offers each frame to the engine. The engine takes Pdelay frames only (destination `01-80-C2-00-00-0E`, EtherType 0x88F7, messageType 2/3/10).
  - The engine's frames enter the `tx` flow by a direct call.
  - Own frames leave in a zero-delay event, as INET's Gptp sends do.
- **Timestamps:** from the interface's PHY signals, associated by tree id.
- **Logs:** per port, `…trafficConditionerLayer.engine.pdelay.csv`, with integer ps.
- **Identities:** clockIdentity 0xa1 (NW-TT) and 0xd1 (DS-TT), portNumber 1.

## Deviations from the design (`migration/m2-s4-design.md`, revision 2)

| Item | Design | Implemented | Reason |
|---|---|---|---|
| Module structure | Classifier + INET `PacketMultiplexer` + engine | Two `TtPdelayFlow` (rx, tx) + engine; the engine injects into the tx flow by a direct call | Protocol registration would otherwise be forwarded into a gateless engine. Same function, fewer moving parts. |
| G0 recorded parameters | Every scalar/statistic identical | Identical, except one ideal-channel object per translator recorded under the new module instead of `measurementLayer.upperLayerOut` | Inserting a module necessarily moves that channel object. It is the only difference, and it is listed explicitly in the gate. |
| F5 (reordering) | Hold Resp until after its Follow_Up | Injector sends a Resp_FU for the same seq ahead of the Resp (`fuBefore`) | Both responders (INET GM, nascTime) send the Resp_FU only after the Resp is transmitted, so holding the Resp deadlocks. Reordering needs the medium, so it is emulated there. |
| Fault expectations (design 8.3) | F1 orphan 1; F3/F12 → multipleResp; F7–F9 orphan 1 | F1/F2 (dropped before transmission): no Follow_Up, so no orphan. INET GM: a Follow_Up per transmitted Resp, so lateAfterFault 2 (5GS F3) and lateDuplicateFU (5GS F3L). Unit F7–F9: the injector's replacement packet is not the responder's own, so no Follow_Up and no orphan. F12: the first Resp_FU leaves before the second Resp, so late duplicates, not multipleResp. | Corrected after the first runs. Each follows from the responder's sending rule or from frame timing, as explained in the rows. The checker requires the exact values. |
| Negative-control row sets | N1: T1, T2, L1, L2; others mostly L1 | N1 also fails T3, T4, F, S3; every control that corrupts the NW-TT value also fails S3 (it uses that value); N3a fails only L1 and S3 (the log keeps t4's first bit, so not T4); N3b fails L2 and S2 (S3 uses PCAP first bits, so it cannot see the mistake) | The checker evaluates every row on every control. |
| N3c | "Predicted indistinguishable" | Indistinguishable **by the value** (D = 50 000 ps); detected through the logged timestamps against PCAP (L1) | The checker compares logged times with PCAP, not only D |
| N4b / N4c signatures | 418 000 ps; 50 ns + (t4″ − t4)/2 | 417 998 ps (the duplicate's t4 also changes the next nRR); N4c = ((t4″ − t1) − (t3 − t2))/2 = 786 000 ps | Exact values are computed from PCAP with INET arithmetic |
| R1 | M2-S1 rows C1–C14 on M2S4 runs | Subset: per-frame accounting, ingress and egress events = PCAP, R = PCAP out − in | The full M2-S1 checker is bound to the M2-S1 config set |
| R2 | Equal application frames and order | Equal order for frames delivered in both runs; frames in flight at the end, or dropped under load, are reported. **R2b added:** an attribution control (`M2S4-ctl-nopdelay(-load)`). | The latencies change (see Limitations) |
| W1 | Exact prediction | Report only (no residues occur in these runs) | — |

## Limitations

- **5GS timing baseline changes.** Without Pdelay traffic in the 5GS, Simu5G schedules the remaining traffic differently.
  - Idle seeds: about 75 % of UL application frames shift by tens of ms; a few DL frames shift.
  - R2b proves this comes from the traffic change, not from the engine.
  - Consequence: M2-S1's per-frame latencies do not transfer to M2S4 runs. Any later stage (M2-S5) must use its own M2S4-based runs as its baseline.
- **Ideal clocks.** nRR = 1, and the TT clock is simulation time. Rate-ratio handling is computed but not validated.
- **Symmetric peer delay.** U3 shows the exact error for an asymmetric link. One-way delay is not measurable by this method.
- **DS-TT requester off in the 5GS scenario.** The INET slave has no responder and aborts on Pdelay_Req (design F4). The requester is validated engine-to-engine only.
- **NW-TT responder** is validated engine-to-engine only (the INET GM never initiates).
- **INET peers.**
  - The INET GM writes responder identity 0, so responder changes cannot be detected toward it.
  - The INET slave (release build) accepts negative or duplicate results silently; N3b shows this.
- **Wire fidelity.** Timestamps travel as ps inside the simulation. Wire truncation is reported (W1), not simulated.
- **802.1AS behaviours not modelled.** The fault policy is nascTime's, provisional pending 802.1AS-2020 clauses 11.2.19/11.2.20 [unverified]. Also not modelled: asCapable driving Sync, CMLDS, multiple domains, and management data sets.
